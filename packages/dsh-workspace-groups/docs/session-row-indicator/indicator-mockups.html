同一棵树，六个方案，可点击收缩。层级是 工作区分组 → 工作区 → 工作区下的子工作区 → 放进会话分组的子工作区，再各带一段未归组会话。 缩进、行高、图标列、引导线、色阶都照 rows.module.css 复刻，只有指示器与「会话」小标题随方案变化。 六张卡片并排一行、横向滚动，卡片本身不换行。 功能基线一致靠结构相同拿到：六张卡片的头部行数、控件种类与文案行数都一样，因此六棵树天然从同一条线开始， 不需要上半部分留白去凑。卡片里的按钮只作用于本卡片，想横向比对同一档收起态时用顶部那排按钮一次推平六张。

「选中态」通道（每张卡片各有一个下拉）

底色被状态占用之后，「当前会话被选中」就失去了表达位置。现状的选中样式是 background: var(--dsw-alias-interactive-bg-hover)，与悬停同属性同值—— 在①–④ 里靠整行变灰够用（官方就是这么写的），而 ⑤⑥ 的状态底色写的是同一个属性， 于是带状态的会话完全显示不出选中。下面几档给的是"改用哪条通道"的不同答案。

中间三档（叠层 + 内描边 / 只内描边 / 淡叠层 + 加字重）只作对照： 落地的插件版本一条描边都不加。官方 active / selected 只有底色，加描边会与设计不一致。

默认值随样式而定，但这一行控件六张卡片都有——能调整的基础功能一致，差的是默认取哪一档： ①–④ 的底色本来透明，选中就用官方那层浅灰，没有要解决的问题；⑤⑥ 的底色被状态占用，才需要「加深」这条新通道。 「加深」也只对有强调色的行生效：运行中 / 待交互有自己的色相，把浓度提上去即可——色相说明是哪种状态，深浅说明是否选中； 空闲与完成本来就没有强调色，与官方完全一致，不另加深（完成若给一抹绿，整段会长期泛色）。

顺带一处权重坑：.row[data-state]:hover 比 .rowSelected[data-state] 权重高， 选中那档因此必须自己再带一档 :hover，否则选中的运行行一悬停就被较浅的悬停值盖回去。插件里两处都写了。

收起态该看什么

  • 收起后唯一还在表达层级的只有缩进与引导线。展开时「会话」小标题、状态图标、段间 12px 间距 都在帮忙；一收起，每个容器只剩一行「图标 + 名字 + 计数」，层级全靠 padding-left。
  • 会话文本比容器名多缩一格（44 对 8、60 对 40），间隔够读；真正的问题是深层子工作区： 它的名字 x=88，而它自己直属会话的标题 x=92——只差 4px，收起后两者几乎同列。
  • 收起态的「里面有东西」这件事，本包目前只有分组头在表达（会话数）， 工作区行没有任何计数；一个收起的工作区里如果只有子工作区、没有直属会话，界面上看不出它非空。 勾上「收起时显示后代数量」可以看到补上这一格之后的样子。
  • 工作区行的文件夹图标随开合换成开/闭两态（照官方），这是收起态里除缩进外唯一的层级信息； ⑥ 的绝对定位状态图标不妨碍它，因为容器行根本没有状态。
