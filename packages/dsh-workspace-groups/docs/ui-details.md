# 交互细节与官方对齐依据

各交互面（行菜单、右键菜单、命名、时间、状态点、悬停卡片、搜索、添加工作区、工作区分组、工作区选择器）的具体行为，以及每条取舍对齐的是官方哪一处实现。README 只列功能清单，逐条论证在这里。

## 容器行的按钮形态

三类容器行共用同一套行尾操作位：`...` 管理菜单 + 可选的新建会话按钮。工作区行与官方 `ui-workspace` 逐项对齐，会话分组行与工作区分组行刻意复用同一布局（同一 `.rowActions` 容器、同一悬停显隐规则），因此三行不会各自漂移。工作区分组行不挂新建会话按钮：它的语义（在该分组里新建会话）无处落，新建工作区的入口在区域 header。

| 行 | `...` 菜单 | 新建会话 |
| --- | --- | --- |
| 工作区 | 新建分组 / 重命名 / 移动到分组… ▸ / 移动到… ▸ / 删除工作区 | 在该工作区新建会话（与官方 `onCreate` 语义一致） |
| 会话分组 | 重命名 / 删除会话分组 | 在该分组所属工作区新建会话，并归入该分组 |
| 工作区分组 | 重命名 / 删除工作区分组 | —（不渲染） |

图标一律取 primitives：`IconEllipsisOutlineRegular` / `IconNewChatOutlineRegular` / `IconEditOutlineRegular` / `IconTrashOutlineRegular`。

分组行行尾的**会话数与工作区分组行尾的工作区数**显示时只给数字本身，不带「个会话」这类单位——官方字典里的 `sessions.count.*` 虽然存在，但在官方组件里从未被引用，因此不照抄。两者与 session 行的相对时间同格同形（`--dsw-alias-label-tertiary`、`12px/20px`），悬停 / 菜单展开时与会话行的时间一样隐去，把行尾让给浮现的操作按钮。

**「新建分组」收进 `...`**：它不像新建会话那样高频，因此不占行内位置。行内那枚按钮交给「新建会话」——官方工作区行在 0.1.7-rc.1 就是用它自己的新建会话字形（`IconNewChatOutlineRegular`），本包跟着对齐，不再是 `+`。

菜单里的「新建分组」带 `+` 图标，与官方 `menu.addWorkspace` 用 `IconPlusOutlineRegular` 的写法一致；官方菜单项的两个图标（`IconEditOutlineRegular` / `IconTrashOutlineRegular`）原样复用。

**分组行的新建按钮建完会话后自动归组**：先走官方导航服务开一个新会话，再用本包既有的 `moveSession` 把它移入该分组，不另造「在分组内建会话」的宿主接口。与工作区行的按钮一样，建之前会展开所在工作区；分组行还会展开分组本身，否则新会话会落在折叠区里看不见。

**每次创建都重摆位置**：按钮完成后无条件把会话摆到本次创建指定的位置——分组行归入该分组，工作区行移出分组（归入未归组区）。工作区行那一步不能省：新建复用的是该工作区已有的空白会话，若它先前是在某个分组里建的，工作区行的按钮复用到它时必须把它从分组里摘出来，否则它的位置会停在上一次创建的地方。

**新建会话复用同工作区的空白会话**：行内那枚按钮调的是官方导航服务的 `openWorkspace`，它先在该工作区里找一条已存在的空白会话（同一个工作区路径、未被归档），找到就复用，否则才调 `create`；然后把它选中并切到会话面板。这条路径与官方 `WorkspaceBrowser` 的新建按钮完全一致，因此连点两次不会攒出两条空会话。本包不自己拼 `create` + `open`——那会与官方组件产生两套行为（见本文「会话操作菜单」一节的复用约定）。

`openWorkspace` 内部还用 `ctx.layout` 起了导航守卫：点完立刻切走时这次新建会被取代，与官方行为一致。它返回 `void`，会话 id 因此从它的 `beforeOpen` 回调里取（官方只在这轮导航仍有效时才回调），被取代时回调不触发，本包也就不再摆位置。这条守卫是官方服务自带的，本包不需要为此引入 `layout` 依赖。

分组行的 `...` 与工作区行一样是**管理操作菜单**，不承担建造型操作：「新建分组」属于工作区行，分组行的高频建造操作就是行内那枚新建会话按钮。

**会话行尾的 `...` 打开会话操作菜单**：外观、位置与悬停行为都对齐官方，菜单里既有官方三项操作，也有本包的归组项（见本文「会话操作菜单」）。

**只有用户创建过分组，才会出现分组结构。** 没有分组时，会话直接平铺在工作区下，与原生列表一致；未归组的会话也平铺在工作区下，不会被塞进一个凭空造出来的「未分组」分组。

一个会话至多属于一个分组：移入新分组时会自动从原分组摘除。

## 会话操作菜单

行尾 `...` 打开菜单，内容分两段：官方三项 + 一条分隔线 + 本包的归组项。行右键唤出的是同一份条目与同一段分派（见本文「行右键菜单」）。

| 段 | 项 | 行为 |
| --- | --- | --- |
| 官方 | 重命名 | 打开重命名对话框，提交走官方会话对象 |
| 官方 | 分叉会话 | 官方 `ctx.uiWorkspace.forkSession`，分叉后打开子会话 |
| 官方 | 归档会话 | 官方 `ctx.uiWorkspace.archiveSession` |
| — | *分隔线* | 只在两段都存在时画 |
| 本包 | 移动到… ▸ | 二级菜单列出该工作区的其他分组 |
| 本包 | 取消分组 | 仅当会话已归组 |

会话行与工作区行的归组一级项**共用「移动到…」这一句文案**（`moveToGroup` 与 `moveToVirtualWorkspace` 两个键同值）：两处都是「点下去还要选一个目标」的二级菜单父项，措辞分工一致；层级由所在菜单本身区分（会话行菜单只有一个工作区内的分组概念，工作区行菜单只有一个工作区分组概念），文案不必再各自加限定词。二级子菜单也都只列目标分组，不混进「移出 / 取消」——那是解散当前归属，本包作为一级项平级渲染。

**官方三项不抄官方实现，而是直接复用官方接口**（本仓库「优先复用官方既有接口」约定的延伸）：

- 动作调用官方既有面 —— 分叉/归档走 `ctx.uiWorkspace` 服务，重命名走 `ctx.sessions.binding(id).session.rename()`。这三处正是官方会话菜单内部调的同一批接口，因此官方改行为时本包**自动跟随**，不需要重新对齐。
- 文案与图标取官方 —— 绑官方 `workspace` 命名空间（`rename` / `menu.fork` / `menu.archiveSession` / `rename.session.title` / `field.sessionName`），图标取 primitives 的 `IconEditOutlineRegular` / `IconBranchOutlineRegular` / `IconArchiveOutlineRegular`。重命名对话框的「取消 / 关闭」是通用词，走官方 `common` 命名空间的回退链。
- **只在类型层依赖官方包**：`package.json` 把 `dsh-client-ui-workspace` 列为 peer + dev 依赖，但只 import type。因此官方一旦改键名或改服务签名，`tsc` 会直接报错，而不是运行期静默显示成原始键名。运行期产物里不含官方代码（bundle 的 `require` 仍只有 primitives / react / react/jsx-runtime）。

「未分组」桶里的会话没有工作区归属、没有分组可落，因此那里只留官方三项。宿主未加载官方 `ui-workspace` 时（本包的区域本来就依赖它供的 `useWorkspaces` 等全局 hook），官方三项与行尾时间**整体不渲染**，不留点不动的死按钮。

## 行右键菜单

工作区行、分组行与会话行都可以右键唤出操作菜单。它是行内 `...` 按钮的 **捷径**，不是第二套操作：条目与分派函数都直接取自该行的 `...` 菜单，两个入口下同一个 id 落到同一段代码上，因此不会各自漂移。`...` 按钮保留，键盘与触控仍靠它。

| 行 | 右键菜单条目 |
| --- | --- |
| 工作区 | 新建会话 / 新建分组 / 重命名 / 移动到分组… / 移动到… / 删除工作区 |
| 分组 | 新建会话 / 重命名分组 / 删除分组 |
| 会话 | 重命名 / 分叉 / 归档（+ 移动到… / 取消分组） |

容器行比 `...` 菜单**多一项「新建会话」**：在行内它对应那枚按钮，没有菜单形态，右键时补在最前，使右键能触达该行全部动作。那枚按钮本身不变，仍只以按钮形态存在。没有新建入口的行（如「未分组」桶的工作区行）不补这一项，否则就是个点不动的死按钮。

面板落在**指针处**：官方 `Menu` 原语的 `getAnchorRect` 允许直接给定位矩形，官方 `WorkspacePickFlow` 用的就是这个入口，本包因此不必自造浮层。原语在该模式下要求 `anchor` 为空。另外两处与原语默认不同：

- **不随指针离开关闭**。锚在按钮旁的 `...` 菜单用 `closeOnPointerLeave`，因为指针一旦移开按钮，菜单就该收起；右键菜单的指针正停在落点，之后移向条目正是正常操作，跟随离开会让它一移就关。
- **根节点整盒去掉**（`.contextMenu`）。原语根节点是 `position: relative` 的行内盒，而面板本身 portal 到 body、根节点没有 DOM 子节点。留在流里会多出一个空 flex 项，行的 `gap` 照样算，标题与会话数会被推开。规则用 `display: contents`，并把类名写两遍（`.contextMenu.contextMenu`）抬一次优先级：原语自己的根类是单类规则，谁后注入谁赢，而插件样式标签与基线样式表的先后不由本包决定。

右键处理拦掉浏览器的默认菜单（`preventDefault`）并停止冒泡（`stopPropagation`，否则外层若也认右键会同时开两个）。**键盘触发的右键**（菜单键）没有指针坐标，浏览器给的是 `(0,0)`：那时退回量行自身的矩形，菜单落在行旁，而不是被丢到窗口左上角。整行都没有菜单时不挂右键处理，右键保持浏览器默认行为。

菜单项文案与图标：

| 项 | 文案来源 | 图标 |
| --- | --- | --- |
| 新建会话 | 官方 `sidebar` 的 `session.new.label`（「新建会话」） | 官方 `IconNewChatOutlineRegular` |
| 新建分组 | 本包 `newGroup` | `IconPlusOutlineRegular`（同官方 `menu.addWorkspace`） |
| 重命名 | 官方 `workspace` 的 `rename` | `IconEditOutlineRegular` |
| 删除工作区 / 分组 | 官方 `delete.workspace` / 本包 `deleteGroup` | `IconTrashOutlineRegular` |
| 分叉 / 归档 | 官方 `workspace` 的 `menu.fork` / `menu.archiveSession` | `IconBranchOutlineRegular` / `IconArchiveOutlineRegular` |

「新建会话」的文案取官方 `sidebar` 新建按钮的**动词短语** `session.new.label`，与行内那枚按钮的无障碍标签（官方 `actions.newSession.aria`，带对象名）分工不同：菜单项是一次性动作，读作动词短语，与「新建分组 / 重命名 / 删除工作区」一致。图标取官方 `IconNewChatOutlineRegular`（官方新建会话按钮的字形），与本包行内那枚按钮同一个字形；菜单里「新建分组」带的是 `+`，两项因此一眼可分。因此 `regionLabels` 多绑一个官方 `sidebar` 命名空间（`tSidebar`），与本包 `t`、官方 `workspace` 三个座位并列。

## 会话命名

新建出的会话行分两个阶段命名，两段都跟官方走：

| 阶段 | 标题来源 |
| --- | --- |
| 空白（刚新建、还没发消息） | 官方 `workspace` 命名空间的 `session.new`（「新会话」/ New Session），渲染期套上 |
| 正式启用（首个回合落地） | 宿主标题服务投影的显示标题（摘要名），随会话列表快照自动更新 |

空白会话的**存储**标题取空串，而不是拿宿主给的后备标题顶上 —— 后备标题是工作区目录名（`displayTitleOf` 的 `title → cwd basename → id` 链），把它当成新建会话的名字会显示成 `dsh_plugins` 这种目录名。这正与官方 `ui-workspace` 的 `sessionTitle` 相同：`session.blank ? "" : session.displayTitle`，显示名留给渲染期本地化。因此 `labels.newSession` 是官方键，本包字典里没有副本；空白行也不进搜索。

空白行同时**不挂行尾菜单**：还没发消息的会话没有可重命名、分叉或归档的对象，官方 `SessionNodeItem` 对空白行同样整条省略号都不渲染。行尾时间也照官方隐去。首个回合落地后，标题服务投影出摘要名，行上恢复常规的时间与菜单。

**空白行固定排在所属区段最前**，其余会话按最近更新倒序（`compareSessionRows`）。它是刚点出来的那条占位行，还没有自己的内容时间，排在分组内 index 0 或未归组区最上面才符合「刚新建的就是这条」的预期；一旦启用就回到与其他会话同一套排序。这也是它唯一享有的一处排序特权，不额外存储任何顺序。

## 行尾最近更新时间

会话行尾显示官方风格的紧凑相对时间（`刚刚` / `5分钟` / `2天`），悬停或菜单展开时让位给 `...` 按钮 —— 与官方同一处 CSS 互换（`time` → `ellipsis`）。

格式化完全复用官方：分桶交给 primitives 的 `relativeTime`（官方 `ui-workspace` 的 `timeLabel` 用的同一个函数），文案交给官方 `workspace` 命名空间的 `time.now` / `time.minutes` / … 键。基准时刻与官方一样在渲染时取 `Date.now()`，官方没有 ticker，本包也不自造一个：分钟级的精度跟着其他重渲染刷新足够。空白（新建中）会话行不显示时间，与官方一致。

## 会话状态点

行首那一列放官方 `@deepseek-ai/dsh-client-ui-primitives` 的 `StateDot`，判定规则与官方 `ui-workspace` 的 `sessionStatuses` 逐条对齐：

| 优先级 | 条件 | 状态 | 外观 |
| --- | --- | --- | --- |
| 1 | 等待审批 / 计划待审 / 等待回答 | `warning` | 琥珀点 |
| 2 | 本会话正在运行 | `ongoing` | 蓝色追光方阵 |
| 3 | 有运行中的子代理 | `ongoing` | 同上 |
| 4 | 本轮已完成、尚未打开 | `done` | 绿色点 |
| — | 空闲 | 不画点 | 槽位留空 |

四项事实都取自 ui-session 的**统一状态快照**（`useSessionStatus`，`SessionStatusSnapshot` 里的 `pendingInteraction` / `running` / `completionUnread`），与官方 `sessionNode` 同一分工：状态快照优先，会话摘要里那份 `running` 只作兜底。等待审批时会话可能并不在 `running`，因此这件事不能从会话摘要里推。

运行中子代理数照官方 `runningChildCount`：读父会话自己那份宿主投影 `projectionsBySession[parentId].values.subagentCatalog`，数其中仍在运行的直接子代理。0.1.7-rc.1 之前本包沿 `byId` 里 `origin === 'subagent'` 的行按 `parentId` 自建脉络上溯，那一版起官方的目录投影已经承担了这件事，本包改读同一格。目录缺失（宿主没装子代理插件、投影尚未到达）时为 0。

空闲态**不画点但保留槽位**，因此标题的横向位置与工作区标题始终对齐。不认识的待交互种类（其他插件发布的）会被忽略，而不是画一个没有文案的点。

## 悬停详情卡片

工作区行与会话行悬停后浮出官方 `HoverCard`，把行上被截断的值补全。两张卡片都复用官方 `ui-workspace` 的既有实现与语言包，不另造浮层：

| 行 | 卡片正文 | 点一下复制 |
| --- | --- | --- |
| 工作区 | 工作区名 / 目录路径（home 缩写）/ `创建于 2026年9月14日 03:31` | 完整目录路径 |
| 会话 | 完整标题 / `5分钟前` / 逐条状态（状态点 + 文案） | 会话标题 |

三种取舍与官方逐条对齐：

- **缩写只影响排版**：POSIX home 及其后代缩成 `~` / `~/…`（`utils/pathUtils.ts`，与官方 `abbreviateHomePath` 同规则，Windows 风格路径整条跳过），复制出去的仍是完整路径。home 来自宿主固定事实 `ctx.remote.$host`，本包照官方 `hostInfo` 的做法把这个源放进 inject 面的 `hooks` 隔间，由渲染器绑成 `useHostInfo` 选择器。
- **会话卡片连空闲也列一条**（官方 `status.idle`），行首那个点则不画：两者从 `data/status.ts` 的 `sessionStatuses` 同一次推导出发，取舍只在 `rowStatusDot` 那一层，因此卡片与行首的点不会各说一套。卡片那份相对时间套官方 `time.ago` 的「…前」模板，`刚刚` 那一档保持原样——官方注明「now ago」不成话。
- **两种面板开着时都让位**：行内 `...` 菜单与行右键菜单。官方只抑制前者；本包多出一个右键菜单，两处都叠卡片会互相遮挡，因此那两份开合状态一起参与判断（右键菜单由此多暴露一个 `open`）。

另有两条降级路径：宿主没加载官方 `ui-workspace` 时官方文案整体拿不到，卡片**整体不挂**而不是浮一个空壳；「未分组」桶的工作区行不是真实工作区（没有目录与创建时刻），官方在那里同样不给卡片，本包照此。空白（新建中）会话行的标题是语言包的占位文案而非会话内容，那张卡片只读、不带复制入口。

卡片正文的样式取官方 `ui-workspace` 的三档文字色常量：卡片底色在两种主题下都是原语写死的深色（`--dsw-hovercard-bg`），因此**不能**用随主题翻转的 `--dsw-alias-label-*`——浅色主题下那些是近黑色，落在深色卡片上会看不见。

卡片那层包装（官方 `HoverCard` 的根节点是个 `display:block` 的 span）会让会话行不再是 `.sessions` 的直接子项，因此层级缩进的选择器多写一档 `> * >`（见「层级缩进」）。

### 贴右缘时的翻转

官方 `HoverCard` 自己算位置：取锚点矩形的 `right + 8` 当 `left`，**只夹垂直方向**，也没有给调用方任何方位选项。产品形态下区域在左侧栏，向右展开正好；对照模式下区域挂在右侧栏、贴着窗口右缘，卡片就会整块开到屏幕外。官方 `Menu` 的二级面板（`left: calc(100% + 10px)`）是同一个毛病。

两处都靠 `body` 上的 `data-wg-flip` 标记翻转，但难点不同：

| 浮层 | 位置来源 | 翻转方式 |
| --- | --- | --- |
| `Menu` 二级面板 | 样式表里的 `left` | 改 `left` / `right`，常规选择器即可 |
| `HoverCard` 卡片 | 原语算出的**内联** `left`，随滚动与改变尺寸重写 | `!important` 压过内联样式 |

只有面板本身翻转，本包塞在子菜单父项行尾的那个箭头（见本文「工作区分组」）**不跟着镜像**：它恒指向右，翻转态下面板从左侧展开时箭头方向与展开方向相反。这是有意的取舍，不额外加一条 `scaleX` 规则去纠正。

卡片还多一层麻烦：它的盒子 portal 到 `document.body`，与官方左侧栏的卡片同处一个父节点，因此选择器必须限定在本包自己的卡片上——正文通过 `ref` 给自己那张卡片打上 `data-wg-hover-card`，样式靠它区分。这个标记**刻意不清理**：正文在复制反馈的 1 秒里会被原语换成「已复制」提示，那次卸载若顺手摘掉标记，卡片刚好在用户盯着的时候弹回屏幕外。

要不要翻由区域**实测**的矩形决定（`utils/flip.ts` 的 `flipPlacement` + `useFlipMarker`），而不是 `COMPARE_MODE` 常量：宿主列是拖出来的，编译期常量只能表达「在对照模式」，表达不了「此刻右边还剩多少地方」。落点写成卡片右缘距窗口右缘的距离，经 `--wg-flip-right` 传给样式——用具体像素而不用 `calc(100vw - …)`，`100vw` 含滚动条宽度，与 fixed 定位的参照系不是同一个。

## 未分组的工作区

不属于任何工作区的会话（典型来源：工作区被删除后遗留的会话）会收进列表末尾一个隐式的**「未分组」工作区**区段，与官方一致 —— 官方在 `groupByWorkspace` 里把无所属会话收集成 `workspaceId === undefined` 的分组，标题取 `group.ungrouped`。

这个区段只在存在无所属会话时才渲染，因此平时不可见。它的会话行**不带**行尾归组菜单：这些会话没有工作区归属，归组操作无处落。它的工作区行也**不带**新建会话按钮：官方虽然照常渲染这个按钮，但处理函数被 `workspaceId !== undefined` 拦成空操作，是个点不动的死按钮；这里直接不渲染。

注意这与工作区**内部**的分组是两回事：工作区内不会凭空造一个「未分组分组」——未归组的会话直接平铺在工作区下。工作区一级的「未分组」容器是另一个层级的概念。

## 工作区分组

**工作区分组**是把一组工作区打包管理的容器，只出现在列表**最外层**（根节点），不会落在某个工作区内部。它与会话分组是两个层级的不同概念，名字里带定语正是为了把这一点说出来：

| 层级 | 容器 | 装什么 | 在哪 |
| --- | --- | --- | --- |
| 根节点 | **工作区分组** | 工作区 | 列表最外层，可嵌套 0 层 |
| 工作区内 | 分组 | 会话**与子工作区** | 某个工作区内部，可嵌套 0 层 |

会话分组里可以放子工作区之后，父工作区体内分三段，顺序是「**子工作区 → 会话分组 → 平铺会话**」（会话分组内部同序）：先文件夹后文件是资源管理器的惯性，会话分组排中间是因为它既可能装会话也可能装子工作区。三段的缩进读得出哪几行是会话——会话行的状态指示器不占行内流，它的标题因此比同级容器的名字左一格，不必再加一条「会话」小标题。完整设计见[子工作区嵌套](sub-workspace-nesting.md#三段靠指示器区分不再用小标题)。

**两个入口，两种语义。** 它们不是二选一，也不是两套实现——都落在同一个命名框与同一段提交流程上，只差草稿里带不带当前工作区：

| 入口 | 在哪 | 语义 |
| --- | --- | --- |
| header 图标按钮 | 区域 section header 右侧，与「添加工作区」并列（宽栏 28px、窄栏 36px） | 建一个**空分组** |
| 工作区行 `...` → 移动到… ▸ → 新建工作区分组 | 工作区行菜单的二级子菜单 | 建组**并把当前工作区放进去**，一步到位 |

**header 那个是一眼可见的入口。** 工作区分组是根节点上的容器，建它不该只藏在某个工作区行的菜单里——尤其在没有归组任何工作区时，用户需要先看到「能建组」这件事。它排在「添加工作区」左侧：建组是更轻的一步（不开 picking 交互、当场弹命名框），不占最右那个高频位置。头部与窄栏都渲染它。

**行菜单那个是顺手用的入口**，针对的场合是「移动时发现没有合适的分组」：那时两步（先建、再移）应该压成一步。因此它的子菜单把建组与各候选分组排在一起，而不是拆成两个一级项让用户先在脑子里过一遍有没有分组。**「移出工作区分组」不在这个子菜单里**：它不是「移动」，而是解散当前归属，因此作为一级项排在「移动到…」下方，与它平级——合成一条子菜单会把「离开」藏进「进入」的入口里。

工作区行 `...` 菜单的完整顺序与各项的显隐：

| 项 | 何时出现 |
| --- | --- |
| 新建分组 | 总是 |
| 重命名 | 总是 |
| *分隔线* | 有归类操作块时 |
| 移动到分组… ▸（各祖先体内可移入的分组） | 该行至少有一个祖先持有分组、或它当前已在某个分组里时 |
| 移出分组 | 仅当前已在某个分组里时 |
| *分隔线* | 有工作区分组上下文时 |
| 移动到… ▸（新建工作区分组**…** / 各分组名） | 该行有分组上下文时（未分组桶的工作区行没有） |
| 移出工作区分组 | 仅当前已归组时；未归组时这一格不占位、不禁用 |
| *分隔线* | 有归类操作块时 |
| 删除工作区 | 总是，带 `danger` |

**两组归类操作各成一个块，块间与删除之前都画分隔线。** 两者进的是不同层级的容器，一级项文案又只差一个词（「移动到分组…」与「移动到…」），不分开读起来像同一个动作的两条路径。删除项前面那条线只在**真的存在归类块**时画：未分组桶里的工作区行没有归类操作，给它画一条线就是把它从空气里隔开。

**两个归组一级项进的是不同层级的容器**：「移动到分组…」进的是父工作区**体内**的会话分组，「移动到…」进的是**根节点**的工作区分组。两者平级、互不影响，顺序上「移动到分组…」在前——它是离当前工作区更近的那一层。

**只有「移动到…」带图标**（`IconVirtualWorkspace16`）：那个字形画的是虚拟工作区分组，是它进的那一层容器的标记。「移动到分组…」进的是父工作区体内的会话分组，另一个层级，因此不带图标——带上会把两个层级的入口画成同一个东西。

「移出分组」与「移出工作区分组」都**不带图标**：它们是移出动作，不是可移入的目标，与带图标的行项目（`+` / 铅笔 / 文件夹加号）有意区分。

**建组那一项不带图标、名字带省略号**，因为它是这个子菜单里唯一的**独立动作** 而不是一个可以移入的目标：省略号表明「点下去还要再填一次名字」（官方 `menu.addWorkspace`（「添加工作区…」）与 header 的 `workspace.add`（「添加工作区」）就是这个分工，本包照此拆成 `menu.newVirtualWorkspace` 与 `newVirtualWorkspace` 两个键）。不带图标顺带解决了两件事：官方 `Menu` 的项是 `gap: 8px` 的 flex 行、图标槽只在有图标时才渲染，因此**同一列表里混着带图标与不带图标的项会让标签左缘错开**——这个子菜单里三项都不带图标，标签因此对齐；同时也不会与一级菜单里带 `+` 的「新建分组」（会话分组）撞形。

「新建」排在最前（与工作区菜单里「新建分组」在前同一取舍），「移出」是破坏当前归属的那一条，排在最后。一级项本身**不禁用**：即便一个分组都没有，它下面还有「新建」可点，因此不存在「点下去什么都不发生」的死入口。

**带二级菜单的一级项在行尾带一个右箭头**（工作区行与会话行的「移动到… ▸」）。官方 `Menu` 原语没有表达「悬停展开」的槽位：`MenuItem` 只有 `id` / `label` / `icon` / `disabled` / `danger` / `submenu`，行内只渲染「前导图标 → 文案 → 尾部选中标记」三个槽，`Menu.module.css` 里也没有箭头的 `::after` 或字形规则；子菜单父项只有 `aria-haspopup` / `aria-expanded` 这类**无障碍**信号，肉眼没有任何提示——二级菜单因此只能靠悬停碰运气发现。本包自己补上这个可见信号：

- **箭头塞进 `label` 里**（`menus.tsx` 的 `submenuParentLabel`），由一个两端对齐的 `.menuLabel` 推到行尾。`label` 是 `ReactNode`，`submenu` 父项又不渲染尾部选中标记（原语只在 `selectedId` 命中且 `selection: 'check'` 时画），因此行尾这一格是空的，箭头不会与它相撞。
- **图标取官方现成的字形**：`.menuArrow` 用 primitives 的 `IconChevronRightOutlineRegular`，与 composer slash 菜单给「可进入目录」候选画的那个行尾箭头同一个字形、同一处位置（那个菜单是官方自绘的 `MenuView`，同样在原语之外自己补了这个槽）。色阶取 `--dsw-alias-label-tertiary`，与官方项图标同档。
- **子菜单为空时不画**：原语只在 `submenu` 非空时才把该项当子菜单父项（不展开、键盘也不进入），此时箭头就是在指一个展不开的菜单。会话已在唯一分组里时那条「移动到…」项正是这种情况。
- **箭头恒指向右，不随翻转变化**：区域右缘放不下浮层时二级面板会翻到列表左侧（见本文「贴右缘时的翻转」），箭头不跟着镜像。

**两次写，因此可能留下空分组。** 行菜单那条路径是「建组」+「移入」两次宿主调用（两个接口各管一件事）。建组成功而移入失败时会留下一个空分组——那是可恢复的状态，下次移入即可，不必为此加一套补偿事务。

**空分组保留并显示空态文案。** 刚建完分组还没移入工作区是通常状态，因此空分组既不消失也不折叠成一行无内容的头，而是照常渲染分组头与撑开体，撑开体里是「这个工作区分组里还没有工作区」。撑开体要让空态也参与逐个淡入，因此占位文案自带 `data-wg-stagger` 标记。

**未归组的工作区排在所有工作区分组之后，平铺、不带区段头。** 与「未分组桶排在全部工作区之后」同一取舍：没有归入任何分组的工作区不会凭空多出一个显式容器。这一层因此**在没有分组时完全不改变界面**——`rootLayout.groups` 为空、全部工作区都在 `loose` 里，行的位置与没有这个功能时逐像素相同。

**归属记录跟着工作区一起清理。** 删除工作区时先调 `forgetWorkspace` 把它从所有分组的 `workspaceIds` 里摘掉，再清它名下的会话分组（见 [数据存储](data-storage.md)）。工作区没了，留下的归属记录再也不会被渲染，留着只会让元数据与真实列表长期偏离。

分组行本身复用会话分组那一套：同一 `.groupHead` 基类、同样的行尾操作位与可收放槽位、同样的撑开体，因此工作区数、悬停让位、操作位显隐都由既有规则承担。三处不同：它在根节点上，缩进取 `8px`（会话分组头是 `24px`）；它**没有新建会话按钮**——分组里要放的是工作区，而新建工作区的入口在区域 header（`workspace.add`），那枚按钮的语义（在该分组里新建会话）在这里无处落；以及它的行首图标是 **虚线文件夹**（见 [自绘图标](custom-icons.md)）。

行首那两个槽与工作区行同一套：文件夹槽与箭头槽常驻同一个 `16px` 列，静止时显示文件夹、悬停换成箭头，因此切换时标题不位移。**虚线是这里的语义所在**：工作区分组形状上像一个工作区，但本身不是一个真实工作区（没有目录、没有会话），虚线把这个区别画出来；实线文件夹留给真实的工作区行，两者并排一眼可分。

## 区域头部

区域顶部有官方同形的 section header：左侧标题（官方 `section.workspaces`），右侧一组 28px 圆形图标按钮。四个入口同属右侧那一组、紧挨着排在栏的右缘，把这一组推向右的是搜索槽位自己的 `margin-left: auto`（官方同此）——入口组不能再写一个 `auto`，两个 `auto` 会平分剩余空间，把搜索框挤到行中间。

**左侧标题是上下两行，两行合起来是一个按钮**：上行写「工作区」并带一个向下的箭头（箭头紧跟文字），下行写当前聚焦的工作区或工作区分组，点这一整块打开选择器面板。

合成一个按钮而不是分成两个可点区域，是因为两行表达的是同一件事（当前在看哪个工作区，点开可以换一个）——分开只会让「点上面还是点下面」变成一个需要试的问题。箭头因此也不是独立按钮，它就是这块按钮自己的开合指示，无障碍上只有一处 `aria-expanded`，它的标签是「切换工作区：{当前聚焦的对象}」。见下面「工作区选择器」一节。

被否掉的替代方案是「第一行 + 箭头一个按钮，第二行另一个按钮」：焦点落在第二行时少一步（最近的可点区域就是它在说的那个对象），代价是同一件事有两个热区、两处 `aria-expanded` 需要保持一致，而收益只是省下鼠标上移 20px。

**上行与下行是两个层级的信息，因此字号与色阶都分开**：上行是层级名（`工作区`，`label-tertiary` 14px/20px），下行是层级里的取值（当前聚焦的对象，`label-secondary` 12px/17px）。两行同色同字号时读起来像同一个标题被折成了两行，而不是「分类 + 取值」。

**标题这块比官方高一档，因此宽栏的 header 不能沿用官方那条 36px 定高。** 两行各 20px 行高，加上 4px 的下间距正好 44px；而 header 带 `overflow: hidden`（搜索展开时标题要整块收拢淡出），沿用定高会把第二行连同裁剪一起吞掉——界面上只是「聚焦的那一行不见了」，不会有任何报错。带两行标题的那一层因此用 `.headerTitled` 把高度放开成 `auto`，由内容撑。

**那 4px 的命中余量由标题块这一个按钮自己带，基线 `.header` 上那条要撤掉。** 两行在同一个按钮盒子里，因此不能再各自加横向内边距——那样它们的左缘会错开。若把 4px 留在 `.header`、再由按钮用负外边距抵回来，负外边距会**同时缩小标题块的内容尺寸**，第二行反而被截断——实测「全部工作区」只剩「全部工…」。`test/styles.test.ts` 把「第二行不得自带内边距」钉住。

| 入口 | 状态 |
| --- | --- |
| **工作区选择器** | 已实现（上行标题旁的箭头），见「工作区选择器」 |
| **搜索** | 已实现，见「搜索」 |
| **新建工作区分组** | 已实现，见「工作区分组」；入口文案不带省略号，菜单里那份带 |
| **添加工作区** | 已实现，见下节 |
| **视图选项** | 已实现（打开一个自绘面板），见下节 |

排序是「搜索（靠 `margin-left: auto` 顶到左端）→ 视图选项 → 新建工作区分组 → 添加工作区」：越靠右越高频，「添加工作区」占最右。窄栏下只留两个建造型入口（新建工作区分组、添加工作区）与下方的搜索块，标题与视图选项不渲染。

**这一组的宽度上限必须容得下它同时能显示的全部入口。** 容器带 `overflow: hidden`（搜索展开时整组要收拢淡出），宽栏能同时出现三个 28px 入口，因此上限是 `28 × 3 + 4 × 2 = 92px`——给小了不会报错，只是把最右边那个入口整个裁掉，界面上平白少一个按钮。窄栏一行放不下两个 36px 入口（栏宽不足 72px），因此那一层改成竖排、每个入口各占一行，并撤掉宽栏那条定高与裁剪（官方 `.rail .headerActions` 同样把 `max-width` 撤成 `none`）。

**视图选项是一个自绘面板**，位置与字形照官方那个图标按钮（`IconSlidersTwoOutlineRegular`，官方 header 在 0.1.7-rc.1 换成了这个字形）。官方原语 `Menu` 的条目只有「前导图标 → 文案 → 尾部选中标记」三个槽，表达不了「一个开关」，因此照官方菜单面板的外观与交互约定自绘一份，规矩与工作区选择器面板同一套（贴触发器下缘展开、放不下翻到上方、两个方向夹进窗口、指针离开延迟关闭、点外/Escape 关闭、方向键在条目间移动）。

面板分两组。上面是**展示方式**：「按工作区」与「平铺」两条互斥的可选项，行内是「图标 → 文案 → 行尾勾」，图标取官方那组「分组方式」的同字形（`IconFolderCloseRegular` / `IconFlatListOutlineRegular`），当前值由 `aria-pressed` 与行尾那个勾共同表达。下面是**子工作区嵌套开关**，用官方 `Switch` 原语渲染，行内是「图标 → 设置名 → 开关」，图标取官方「按工作区树分组」那一项的 `IconWorkspaceTreeOutlineRegular`——本条开关控制的正是子工作区的树形渲染。文案给的是设置名（「子工作区嵌套」）而不是「启用 / 关闭」这类动作短语，开关的开合由 `aria-checked` 与滑块位置表达；文案跟着状态变会让读屏读出「关闭子工作区嵌套，开关，已打开」这种自相矛盾。条目行本身因此不可点——`Switch` 已经是一个 `role="switch"` 的按钮，行再做成可点就是一层里两个控件。两组之间隔一条分隔线，取官方菜单 `separator` 的同一档。切换即生效、面板不关——用户多半要看着列表确认结果。关闭嵌套前会先弹确认框，见[子工作区嵌套](sub-workspace-nesting.md#开关)。

两条互斥项与开关那条的形态刻意相反：官方 `Switch` 只表达两态布尔，而「选哪一个」没有对应的原语，因此整行做成按钮，点整行即选中，键盘激活由原生按钮行为承担。选中态不加行底色，只靠行尾那个勾——与官方 `Menu` 的 `selection: 'check'` 同一取舍。

窄栏（rail）下与官方一致：标题与视图选项都不渲染，留「添加工作区」（在 header 行里）与它下方独立的 36px 搜索入口，两者都是 `label-primary`。两行标题同样不渲染——窄栏放不下第二行，而且它的作用（换一个工作区看）以「展开侧栏」为前一步，此刻还没有列可看。

## 工作区选择器

header 第一行的「工作区」旁有一个向下的箭头，它打开一个下拉面板，用来把整个列表 **聚焦到根节点上的某一个条目**上。第二行写着当前聚焦的是谁。

### 菜单内容

**菜单只列根节点单元格里的条目**：各虚拟工作区分组，以及没有归入任何分组的工作区。虚拟分组名下的工作区**不单独列出**——聚焦它们与聚焦所属分组看到的是同一片内容，多列一遍只会让菜单长出与列表层级重复的一层。因此聚焦到分组后不能再从菜单里进一步聚焦组内某个工作区；要单独看一个，先把它移出虚拟分组。

没有归入任何虚拟分组的工作区按 **cwd 嵌套层级**展开：父在 0 层，子工作区按层级缩进（见[子工作区嵌套](sub-workspace-nesting.md#工作区选择器里的子工作区)）。虚拟分组体内的父子关系不在菜单里体现——那一整组只由分组名一个条目代表。

被否掉的替代方案是「列出全部工作区，分组名作为分组标题」：任何工作区都能一步聚焦，代价是菜单更长、选组内工作区时还要同时决定列表形态。

三个分区：

| 分区 | 内容 | 顺序 |
| --- | --- | --- |
| **最近使用** | 最近聚焦过的至多 5 个条目 | 最近一次在最前 |
| **置顶** | 被置顶的条目 | 按最近使用顺序，从没用过的排在最后 |
| **全部** | 全部根节点条目 | 与列表的展示顺序一致（先分组、后未归组的独立工作区） |

前两个是**可折叠的分区头，条目直接在它下面向下展开**，没有二级菜单：这两个分区各只装一层条目，飞出一个子面板只会让「点哪个才是我要的」多一层悬停。**「全部」不可折叠、也不带标题**——它是没有标题时默认的那一栏，上面两栏的标题正是因为要与它区分才需要，它自己再写一个「全部」就是同义反复。三栏之间那条分隔线照旧画着，边界仍读得出来。

**「全部工作区」只在已经聚焦时才出现。** 它是恢复入口；没有聚焦时点它不做任何事，留着就是一个点不动的死条目。它是一个**动作**（退出聚焦）而不是菜单条目，因此不带选中标记、也不带那三枚操作按钮——这里的「全部」没有可重命名或删除的对象。

**最近使用为空、或一个都没置顶时，那两组整组不渲染**（不是留一个空的标题行）：菜单初始只有「全部」一块，用过几次之后上面两块才长出来。分区标题因此不会在一次使用前后对不上。

### 置顶

**条目的行结构与工作区行同形**：行本身是一个 `role="button"` 的 div，行尾三枚 16px 操作按钮（重命名 / 删除 / 置顶）嵌在行内的操作位里——与 `WorkspaceRow` 完全一致。行用 div 而不是 `<button>` 正是因为按钮不能嵌按钮；键盘激活由 `handleRowKeyDown` 承担，与工作区行同一套（只认行自身拿到焦点的那一次按键，行内按钮的按键不冒泡上来）。

被否掉的替代方案是「把这三件事收进条目自己的 `...` 子菜单」：与列表里的行菜单一致，但下一级面板又要多一次悬停，而这三件事恰恰是在浏览菜单时顺手做的。也否掉了「行做 `<button>`、三枚按钮做它的兄弟节点」：那样行的可点区比看起来窄，悬停高亮也只盖住行那一截。

三枚按钮都只在该行悬停或自己拿到键盘焦点时出现（沿用 `.rowAction` 那一份规则，两处不会漂移），点击一律 `stopPropagation`，否则会连带聚焦到那个工作区。已置顶的那一枚**常驻可见**（它是这条记录当前的状态，不该只在悬停时才读得到），删除那枚悬停时带错误色（与行菜单里的删除项同一做法）。

**方向键只在「行」这一层循环，不停在行尾按钮上**：否则按一次 ↓ 会逐枚走过三枚按钮，过三条条目要按九次。

**重命名与删除不新造对话框，也不新造宿主接口**：按条目类别转到既有的那两条路径——工作区分组走本包的 `renameVirtualWorkspace` / `deleteVirtualWorkspace`，独立工作区走官方工作区控制器与既有的删除确认框。菜单只是把这些入口搬到手边，因此两条入口下「删掉什么」的语义不会漂移。点下去菜单收起：接下来是对话框，它不该被面板压住。

**字形取官方图钉**：0.1.7-rc.1 的 primitives 新增了 `IconPinOutlineRegular` / `IconPinFillRegular`，本包因此不再自绘。两态是同一枚图钉的描边版与填充版，置顶因此不只靠颜色——色阶在浅色主题下对比有限，实心与描边才是一眼可分的差别。这一版之前本包自绘过一枚斜 45° 的图钉，被否掉的造型与测量方式留在 [自绘图标](custom-icons.md)。

**置顶与取消置顶是同一个宿主方法**（`togglePinned`）：菜单里那一格按钮点下去只表达「反过来」，不区分当前是哪种状态，两侧因此不可能各写一套判断。

被否掉的替代方案是「在工作区行 `...` 菜单里加一项」：与既有行菜单一致，但要多点两层才能置顶，而置顶恰恰是在浏览菜单时顺手做的事。置顶按钮与行本身是两个热区（行是「去这个工作区」，行尾是「把它固定住」），合成一个会让「想置顶却跳走了」。

### 聚焦后的列表

| 聚焦对象 | 列表 |
| --- | --- |
| 工作区分组 | 只显示组内工作区；**根节点那层不再重复渲染组头**（第二行已经写着组名，再出现一次就是同一个名字并排两次） |
| 独立工作区 | 只显示它自己 |
| 无（「全部工作区」） | 与没有这个特性时完全一致 |

聚焦分组时不保留组头，被否掉的替代方案是「保留组头（仍可折叠）」：组内工作区还能整组收起，代价是组名出现两次，而且那个组头的折叠状态与「聚焦」这一层状态会互相打岔。

**聚焦时末尾那个隐式的「未分组」区段整段隐藏**：聚焦就是「只看这一个」，而那些会话不属于任何一个工作区，与当前这片内容无关。

**聚焦的条目已经消失时退回「全部」**，而不是渲染一个空列表：三份记录比列表活得久（工作区被删、分组被解散之后，那个键仍可能躺在记录里），直接按它过滤会让列表整片空掉，而第二行还写着一个已经不存在的名字。工作区被删或分组被解散时宿主也会把那个键从三份记录里一并摘掉（见 [数据存储](data-storage.md)），两处因此是同一套语义的两条防线。

**平铺列表下聚焦照旧生效**，但它不再走「保留哪一段」那条路——平铺没有分段，只能按工作区归属过滤。两者的差别只在一处：聚焦工作区分组时，平铺列出的是该分组的**归属全集**（`workspaceIds`），而不是分组视图里那份**渲染层级**（`roots`）。平铺本来就没有层级，被嵌套的成员与顶层成员一样是这片内容的一部分，按 `roots` 过滤会让它们凭空消失。

## 展示方式

**「按工作区」与「平铺」是同一批会话的两种排布**，行本身（状态点、标题、相对时间、悬停卡片、`...` 菜单、右键菜单）两条路径完全共用，只有外层结构不同。

| 方式 | 列表 |
| --- | --- |
| 按工作区（默认） | 工作区分组 → 工作区块 → 撑开体（子工作区 / 会话分组 / 平铺会话），与没有这个特性时一致 |
| 平铺 | 全部可见会话排成一条列表，没有工作区分组头，每一行各自带它的工作区上下文 |

平铺的成员集合与工作区组织方式无关，因此「未分组」桶里的会话也在其中；可见性判定（归档、子代理来源、只保留当前选中的空白会话）与排序（空白行最前、其余按最近更新倒序）两条路径读同一份实现（`flatSessionRows` 与 `compareSessionRows`），不会各说一套。行的归组菜单在平铺下没有分组上下文，与未分组桶里的行同一取舍：只留官方三项。

**平铺行没有状态位时行首那一格不占位**，标题从行左缘起排——官方 `.flatSessionRowWithoutStatus` 就是这个含义。有状态位时它照常占一格，两种方式下逐行一致。

这一层刻意**不改变工作区分组本身**：分组、归属、嵌套判定都照旧，切回「按工作区」时看到的就是原来的样子。也因为这个取舍，区域底部那两条说明在两种方式下都渲染——嵌套开关是根节点级的设置，关了之后即使当前看的是平铺列表也要说明它被关掉了。

### 为什么是自绘菜单

官方 `Menu` 原语的条目只有「前导图标 → 文案 → 尾部选中标记」三个槽，**没有可折叠的分区头**，也没有挂在条目行尾、只在该行悬停时露出的第二个按钮。三条需求都落不进那个形状，因此面板按原语的**外观与交互约定**自绘一份：

- 落点贴触发器下缘展开（实测菜单顶边落在标题按钮下缘之下 4px），放不下就翻到上方，两个方向都夹进窗口（边距 12px、缝隙 4px，取原语那套的同一个值）；
- 指针离开后延迟 200ms 关闭，与触发器到面板之间的那条缝隙配套——不留这段延迟，用户还没点到条目菜单就没了；
- 点面板与触发器之外关闭、`Escape` 关闭并把焦点还给触发器；
- 方向键在条目间移动（`Home` / `End` 到两端）。

**无障碍上是展开式弹出层而不是 `role="menu"`**：面板里既有可折叠的分区头，也有行尾那枚置顶按钮，而 `role="menu"` 只允许 `menuitem` 一类的子项，两者都塞不进那个模型。面板因此取 `role="group"`，标题那块按钮只声明 `aria-expanded`（不写 `aria-haspopup`——那等于承诺一个 `menu` 角色），标签是「切换工作区：{当前聚焦的对象}」：按钮上可见的文字是「工作区」加一个工作区名，只报名字的话读屏听上去那是一段说明文字而不是一个入口。

**底色、描边与投影必须用官方菜单面板那一套 token**（`--dsw-specific-menu` = `--dsw-alias-bg-layer-3`、`--dsw-elevation-prominent`、`--dsw-elevation-stroke-color` = `--dsw-alias-border-l1`），并把 `--dsw-elevation-stroke-color` 在面板这一层重设，投影里那圈描边才会跟着面板自己的圆角走。层级取官方 `.portal` 面板的同一个 `z-index: 1100`，圆角与最小宽度取官方 `.list` / `.submenu` 面板的 `20px` / `218px`。

这几条不是装饰：面板是**不透明的浮层**，底下就是会话列表。写一个并不存在的 token 名时 `background` 整条失效、面板变透明，后面的会话直接穿过来——而这类错误在界面上不会有任何报错，改完源码在测试里也照样通过。因此 `test/styles.test.ts` 直接断言那几个 token 名，并禁止带回退值的写法（回退值会把「token 名写错」变成「悄悄用了另一个颜色」）。

面板 portal 到 `document.body`：header 自己带 `overflow: hidden`，就近渲染的面板会被它整个裁掉。

**搜索展开时面板收起**：搜索展开时标题整块让位（两行都收拢淡出，指针事件也一并关掉）。面板若还开着，就悬在一片与它无关的结果列表上——它的两个触发器此刻都不可点。因此面板的 `open` 与搜索态相与，搜索一开始它就收起。

### 新建分组时切过去

已在聚焦状态下新建工作区分组时，命名框里多一个「切换到新工作区」勾选项。新建的分组追加在列表最末，用户若正聚焦在某一片内容上（比如某个工作区分组内部），建完分组后新分组落在当前视野之外——界面上就是「点了确定但什么都没变」。勾上这个选项就在建完之后把视图切过去。

它只在已聚焦时出现：正看着「全部工作区」时新分组本来就在视野里，没有可切的目的地，给一个勾了也无事可做的选项只会让人以为它有什么作用。改名时不出现（改名不新建东西）。

## 搜索

官方 `ui-workspace` 的搜索是**两段合并**：本地按标题匹配 + Host 内容检索（`session.search`）。本包只做前一段——**只匹配标题，不接内容检索**，因此结果行没有摘录，也没有「正在搜索 / 内容搜索暂不可用」两态。

匹配对象与官方本地那一段同一口径：**会话标题或所属工作区标题**包含查询词即命中（工作区名可搜，因此输入「前端仓库」会列出该工作区下的会话）。候选与渲染列表同源：归档、子代理来源、以及空闲的空白会话都不进结果。排序照官方：最近更新倒序、id 作稳定次序；条数上限直接读官方会话控制器的 `searchResultLimit`（线上响应契约的同一个数），被截断时给出官方那句「仅显示前 N 条结果」。

**结果行的路径带上分组，并用两档色阶区分**：官方那行元信息只显示工作区名，本包在其后补上分组，形如 `工作区/分组`。两段各自着色——工作区用 `label-secondary`，分组用更深（浅色主题下更浅）的 `label-caption`，一眼能看出哪段是容器、哪段是组；两段同色的话，分隔符两侧只是一条长名字。分隔符本身不单独成类，它落在分组那一段里继承同一色阶，因此两段之间不会多出第三个层级。

**两段之间不能有间距**：第二行那个容器带 6px gap，那是官方留给「工作区名 / 内容摘录」两格的；本包没有摘录，若让两段直接做它的子项，这个 gap 会插进「工作区」与「分组」之间，把一条连续的路径读成两截。因此路径整体是那一行里唯一的 flex 项，自己内部是 gap 为 0 的 flex 行。宽度上限（60%）也挂在这一层而不是段上——挂到段上会按路径自身宽度算百分比，越窄越缩，长工作区名一开始就被截断。未归组的会话只显示 `工作区`，无所属工作区的会话退回官方的 `未分组`——与「工作区内不凭空造未分组分组」的取舍一致。

**动效与交互照官方**：收起时是一个 28px 正圆的图标按钮；展开后该槽位拉满整行、按钮与图标一起缩小，标题向左收拢淡出、右侧入口组向右收拢淡出，整行只剩那个 30px 的圆角搜索框。`Escape` 清空并收起，清除按钮只在展开时出现，点击别处只收回焦点（查询非空时保持展开）。时长与缓动取官方那套 `.18s` / `.12s` + `--ds-ease-in-out`，并在 `prefers-reduced-motion` 下整段落位。

**进出搜索时整块面板淡入**：官方给三种内容体（会话树 / 单列表 / 搜索结果）共用的 `.treeBody` 挂了 `.2s` 的 `wide-in` 动画，三者在它的三元分支里是不同的元素，切换内容体即重新挂载、动画重放。本包的常规列表与搜索结果各有自己的根节点（同一条三元分支），两者都带 `.panel`，因此每次进出搜索各有一段面板级淡入。它与撑开体的逐行淡入是两回事：后者管的是展开撑开体时行逐个露面。关键帧只写 `0% { opacity: 0 }`，终态留给元素自然状态，动画没跑或被打断时面板仍可见；`prefers-reduced-motion` 下整条 `animation` 撤掉（只撤 `transition` 会让面板一直停在不可见）。

窄栏点搜索会先请求展开侧栏，**等列滑动跑完**（官方 `EXPAND_SLIDE_MS` = 300ms）再把焦点交给宽栏的输入框——`focus()` 会强制一次同步布局，抢在滑动中间会把动画卡住。

**点结果会展开折叠层并滚到那一行**：会话可能正躺在收起的工作区分组、工作区或会话分组里，因此打开前先把这三层展开并把查询清掉，落到常规列表后再由该行把自己滚进可视区（与官方 `revealSessionId` 那条路同一取舍）。

## 添加工作区

流程与官方 WorkspaceBrowser 逐段一致：

1. 点入口 → 直接打开 picking 交互（官方在侧边栏用 `addOnly: true`，同样不先弹工作区列表菜单）；
2. 用户在交互里选中一个目录（或取消）；
3. 选中后调官方 `ctx.workspaces.create({ path })` 采纳；
4. 采纳成功 → 官方 `ctx.uiWorkspace.startSession(workspaceId)`，在新工作区里开一个新会话并打开；
5. 采纳失败 → 官方 `folderError.title` 错误框，`folderError.retry`（「重新选择」）重开交互。

picking 交互本身不重写：它整段来自官方 `sidebar.workspaces.directoryFlow` 洞的占用者（native / browse 两种组合都覆盖，见 [与官方实现的复用关系](official-reuse.md) 的「目录选择器」一节）。文案零新增——入口、错误框标题与「重新选择」都取官方 `workspace` 命名空间的既有键。
