# 布局与样式对齐

尺寸、留白、色阶与缩进几何的取值来源如下，并逐项标注哪些数值是官方既有规则的复刻、哪些是本包多出的层级自己的取舍。

## 层级缩进

层级靠左边距与一条竖向引导线表达。每层让出一个 `16px` 图标列，基准是官方工作区行的 `8px`：

| 行 | 左边距 |
| --- | --- |
| 工作区行（含嵌在父工作区体内的子工作区行） | `8px + 16px × 深度` |
| 分组头 | `24px + 16px × 深度` |
| 未归组的会话行 | `24px + 16px × 深度` |
| 分组内的会话行 | `40px + 16px × 深度` |
| 工作区体内「暂无会话」的空态 | `24px + 16px × 深度` |
| 虚拟分组体内「还没有工作区」的空态 | `24px`（那个容器里没有层级） |

**会话行比同级容器多让出一格**（未归组的比工作区行多一格、组内的比分组头多一格）：指示器虽然不占行内流，但它排在行的左缘那 `4~20px` 上，文本必须让开它。多让一格同时让「这几行是会话」由缩进自己读出来，不再需要那条「会话」小标题。

**同一段里所有会话行的标题落在同一条竖线上**，不随状态出现与否位移——指示器绝对定位（见[状态指示器](#状态指示器)），它出不出现都不推动文本。

引导线落在父级图标列的中心，因此每层一处：根节点 `16px`、下一层 `32px`，依此类推。工作区分组是这条链上的第 0 层，它自己不缩进，组内的东西整体右移一格。

**子工作区可以嵌任意层，缩进不能再按固定层数写死选择器。** 层级由 `data/nest.ts` 的 `levelOf` 在 JS 里算好，组件经 `--wg-depth` 下发；样式表只把它当数值用，各档都写成 `基准 + 16px × var(--wg-depth, 0)`，再经 `--wg-row-start` 中转一次。**指示器的落点不跟缩进走**：它恒在行的最左缘（`--wg-indicator-inset`），因此缩进公式里没有它这一项。

层级是**渲染结构上让出了几格**，不是 cwd 祖先个数——两者只在父是纯 cwd 祖先时相等：

| 情形 | 层级 |
| --- | --- |
| 不在任何虚拟分组里的顶层工作区 | `0` |
| 在虚拟分组里、组内没有更近的父 | `1`（工作区分组是这条链上的第 0 层） |
| 挂在父体内未归组那一段 | 父的层级 `+1` |
| 被放进父体内某个会话分组 | 父的层级 `+2`（中间还夹着那个分组头） |

最后一行是**必须在 JS 里算**的原因：容器的让位要累加，一个工作区可以既在虚拟分组里、又被放进其中某个工作区的会话分组，那是两格。曾经把偏移交给 CSS 变量继承（`--x: calc(var(--x) + 1)`），那是**循环引用**——浏览器把整条声明当作无效值丢掉，`var()` 取到兜底的 `0`，于是被放进分组的子工作区与分组头停在同一个缩进上（同为 `24px`），读起来像分组的兄弟而不是组内的内容。这类失效没有任何报错，只能靠断言最终内边距的测试守住。

每个 `.workspace` 都自己下发一次 `--wg-depth`，子工作区因此不会被父的深度顺着继承下来。

缩进步进与层级结构效果参考取自 [`liceses/dsh-workspace-tree`](https://github.com/liceses/dsh-workspace-tree)

空态占位与它所在那一段的行同起点：那句「暂无会话」是**这一层**的说明，浮在父行左侧会读成父工作区的内容。它自己的 `padding-left` 因此也要按 `--wg-depth` 换算——`.empty` 基础规则里那条 `16px 12px` 是给搜索无结果那类固定位置用的，不参与层级。

挂上悬停卡片的会话行外面会多一层包装（官方 `HoverCard` 的根节点），行因此不再是 `.sessions` 的直接子项；缩进选择器为此把 `> .row` 与 `> * > .row` 两档都写着，有没有卡片缩进都一致。

**层级缩进是一组按真实 DOM 结构写的选择器，写错时界面只是「没有缩进」，不会报错。** `test/virtualWorkspaceDom.test.tsx` 因此用真 `react-dom` 渲染一遍，把样式表里所有带 `wg-virtual-workspace-body` 的规则逐条拿去 `querySelectorAll`，任一规则一个选择器都不命中就失败。这条测试已经抓到过一次真实缺陷：工作区行挂上悬停卡片后会被官方 `HoverCard` 的根节点包一层，`> .workspaceHead` 那一档因此不再命中，缩进整段失效——与既有会话行那条同理，必须把 `> * >` 一档也写上。

上面那条缩进选择器的不变量也记在[渲染性能与行级缓存](render-performance.md#钉住不变量)，与折叠体为什么必须 fail-open、行级 memo 要怎样才能命中（含实测数据）并列。

## 状态指示器

会话行的状态指示器**不占行内流**：它绝对定位在行的最左缘（容器栏的左缘），**与层级深度无关**，空闲时整枚不渲染。这与官方 `SessionNodeItem` 不同——官方在行首留一个固定的 `.slot`，空闲时槽位空着，靠它撑住「标题始终落在同一横向线」这条不变量。

本包改成出流，是因为那条不变量换了个更好的办法维持：**同段所有会话行的缩进本来就相同**，指示器出不出现都不推动任何东西。收益是「会话行」这一层终于有了不依赖状态的身份——官方那套里空闲行的行首是空的，三段（子工作区行、分组头、未归组会话行）的文本左缘会因此产生歧义，只能再补一条「会话」小标题把它们分开，而那条小标题嵌套一深就在每个体内都冒一条。

指示器有两种样式，由视图选项面板里的「指示器」一组切换，取值存在浏览器本地（见[数据存储](data-storage.md)）：

| 样式 | 字形 | 内缩 | 说明 |
| --- | --- | --- | --- |
| 图标 | 官方 `StateDot` | `6px` | 默认。运行画旋转弧，待交互与完成画实心圆点 |
| 色条 | 自绘的一根 `3px × 20px` 圆角竖条 | `4px` | 颜色取同一组状态语义词，形状更安静 |

两者都锚在行的最左缘：`left: var(--wg-indicator-inset)`。**落点不读 `--wg-row-start`**——它跟深度无关，恒在容器栏左缘那一处。这两个变量定在**区域根**（`WorkspaceGroupsRegion.module.css`）而不是逐工作区：平铺列表里的行不在任何 `.workspace` 之内，变量落在工作区上会让它整条 `left` 退化成 `auto`，指示器随即压到标题上。内缩那几像素让它读成「浮在行里」而不是行的左边界；图标是 16px 方块，比 3px 宽的色条多缩 2px 才不会有「这是行的边框」的错觉，两者因此不在同一条竖线上（刻意的）。

那 16px 宽的指示器盒是给官方图标用的，**色条不在盒里居中**：3px 宽的色条若居中，左缘会落到 `内缩 + 6.5px` 上，比设计稿的落点右移 6.5px。色条因此靠左对齐（`justify-content: flex-start`），左缘正好压在 `--wg-indicator-inset` 上，与设计稿那根 `::before` 的落点一致。高度取设计稿的 `20px`（行高 32、上下各留 6）。样式经区域根节点上的 `data-wg-indicator` 下发，列表里每一行读同一个值，不必逐行传。

**行的状态底色与悬停 / 选中**：

- 运行与待交互各上一层浅色底，颜色取同一组状态语义词（`color-mix` 到 `10%`）。**完成与空闲不设底色**——完成那次提醒已经由指示器的绿色表达，再铺一层底会让整段长期泛色。
- **没有强调色的行（空闲、完成）与官方完全一致**：悬停与选中同为 `var(--dsw-alias-interactive-bg-hover)`，**同一个属性、同一个值**。官方就是一条声明把两者写在一起（`projectRow:hover, sessionRow:hover, sessionRow.selected`），因此 hover / active / hover+active 三者同色——不存在「再叠一层」，也**没有任何边框**。本包照抄这条，不另加深、不加第二层。
- **只有有强调色的行才加深**：同一色相上把浓度提上去，悬停 `18%`、选中 `26%`。于是色相仍说明是哪种状态，深浅说明「指针在上面」还是「这是当前会话」。这些行**不叠灰**——`--dsw-alias-interactive-bg-hover` 是中性灰，压在饱和蓝上会把色相稀释成糊色。
- 底色一律写 `background-color` 而不是 `background` 简写：简写会把同一元素上另一条声明一起清掉。

一处**权重坑**：`.row[data-wg-state]:hover` 是 `(0,3,0)`，比 `.rowSelected[data-wg-state]` 的 `(0,2,0)` 高。选中那档因此必须自己再带一档 `:hover`，否则选中的运行行一被悬停就被较浅的悬停值盖回去、反而变浅。

这同时修掉一处既有问题：悬停与选中原本写的是同一个属性的同一个值（`background: var(--dsw-alias-interactive-bg-hover)`），本来就分不出「鼠标在这行上」与「这是当前会话」。对照稿与取舍过程见[会话行指示器的备选方案](session-row-indicator/README.md)。

右侧那 12px 值得单说，它是最容易抄错的一处：**官方的右留白不由 shell 提供，而由 `WorkspaceBrowser` 的根节点自己拥有**——shell 的 `regionArea` 先把 `margin-right` 设为 `-12px` 抵消掉，根节点再 `padding-right: 12px` 加回来。本包接替了这个根节点，就必须把那份留白连同三个自定义属性（`--dsh-session-list-edge-inset` / `-scrollbar-width` / `-scrollbar-offset`，官方定义在同一个根节点上、随它一起消失）一起重建，否则 header 的入口按钮与列表行都会一路贴到侧栏右缘。

列表还要再折一层：官方 `.listArea` 用 `-edge-inset` 让列表靠到栏缘，再由 `.list` 把内容推回到离栏缘 12px。本包没有 `.listArea`，因此这两个偏移折进 `.list` 自己的 `margin-right` / `padding-right`。窄栏下本包不渲染 `.root`（只渲染两个入口），右缘因此落在 shell 折叠态的 10px 上，与官方 `.root.rail{padding-right:0}` 一致。

唯一不取自官方的数值仍是**层级缩进的步进量**（`16px`）与引导线：官方只有「工作区 → 会话」两级且两级都不缩进，本包多出的分组层没有可抄的先例，取生态内的既有做法（见本文「层级缩进」）。

文字层级与官方逐条对齐：

- **工作区标题与会话标题同色同字号**：都是 `--dsw-alias-label-primary` 14px / 20px，且都**不加字重**。官方 `ui-workspace` 的 `.title` 是两者共用的类，层级只由行高（34px vs 32px）承担。改用更暗的 `label-secondary` 加 `font-weight: 500` 会与官方不一致。
- 容器行（官方 `projectRow`）底色是 `label-primary`，`label-tertiary` 只属于其中的图标槽。分组标题是官方没有的层级，刻意保留 `label-tertiary` 以示「比工作区低一级」。
- 字号与行高成对写在叶子上（官方 `.title` 即如此）；根节点只设 `font-size: 14px`，**不设 `line-height`**，与官方侧栏根一致。

两处结构性对齐，都是照官方 DOM 复刻的：

- **工作区行**：静止时显示文件夹（展开/收起两态），行悬停时文件夹隐藏、换成实心三角箭头。两个槽都常驻同一 16px 图标列，因此切换时标题不位移。
- **会话行**：状态指示器绝对定位在行的左侧（空闲时整枚不渲染），行尾是操作位。它**不占行内流**，因此标题位置与状态无关——这是本包与官方会话行唯一的几何差异，理由是没有它就得再补一条「会话」小标题（见[状态指示器](#状态指示器)）。

**分组行没有文件夹槽**（分组不是工作区），因此图标列只有箭头一个，也不参与「悬停换成箭头」那套互换；它的行尾操作位与工作区行共用同一个 `.rowActions` 容器与同一份悬停显隐规则。

不过分组行多一处差异：它外面还套了 session 行那套**可收放槽位**（`.rowActionSlot`）。分组行有会话数要展示，而会话数要与 session 行的相对时间落在同一条右缘线上——那就必须让操作位静止时不占宽，否则会话数会被常驻的操作区顶着、退到行中间。因此分组行的结构是「标题 → 会话数 → 可收放槽位（内含操作位）」：静止时槽位收成 0 宽，会话数贴住行右；悬停/菜单展开/键盘聚焦时槽位展开，会话数同时隐去，两者严格互换。

槽位虽然收成 0 宽，**仍是 flex 子项**，与它相邻的那份 `gap` 照算——分组头是 `gap: 6px`，而 session 行是 `gap: 0`，所以会话数还要用 `margin-right: -6px` 把这份多出来的间距还回去，右缘才与 `time` 落在同一条竖线上。展开宽度取 `auto` 而非会话行的 `16px`：槽里是两个按钮（16 + 12 + 16）。

工作区行没有行尾文本，因此保持操作位常驻在流内（只切换不透明度），悬停时标题不位移。

行内操作按钮默认隐藏（并同时 `pointer-events: none`，否则会留下看不见却能点中的热区），只在三种情况下显示：**所在行悬停**、**菜单展开期间**、**键盘导航聚焦**（`:focus-visible`）。

这里刻意**不用** `:focus`、`:focus-within` 和选中态：鼠标点过按钮后焦点会留在按钮或行上，这三条会让按钮一直显示；`:focus-visible` 只在键盘操作时命中，既消除鼠标残留，又保留清晰可见的键盘焦点。官方 `ui-workspace` 同理 —— 它只认 `:hover` 与菜单展开态。

三种显示状态都需要「行」自身获得焦点或悬停，因此行与容器行的 `onKeyDown` 会忽略由行内按钮冒泡上来的按键（`event.target !== event.currentTarget`），否则在按钮上按 Enter 会连带折叠工作区或打开会话。
