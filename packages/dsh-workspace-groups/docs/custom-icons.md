# 自绘图标：工作区分组的字形

工作区分组需要一个官方 primitives 里不存在的字形（「新建工作区分组」入口与分组行），
本文记录这两个字形的构图依据、尺寸测量方式与试错过程。


`src/client/icons.tsx` 是唯一的自绘图标模块，目前有两个：`IconVirtualWorkspace16`
（新建入口与菜单项）与 `IconVirtualFolder16`（工作区分组行）。两者共用官方
`IconFolderClose16` 的文件夹轮廓，`IconVirtualWorkspace16` 只是右上角不闭合、把
缺口留给加号。规范逐条对齐官方 primitives 的内联 SVG：

| 项 | 取值 |
| --- | --- |
| `viewBox` / 内联方式 | `0 0 16 16`，与官方一样内联，**不带 `xmlns`**（官方那几个也没有） |
| 颜色 | 一律 `currentColor`，继承所在行的文字色，不写死主题色 |
| 轮廓 | 官方 `IconFolderClose16` 的**中线**：x `1.5~14.5`、y `2.429~13.5863`、圆角 `1.6736` |
| 壁厚 | `stroke-width: 1.3`，线端 `round` |
| 绘制方式 | 只用描边（`fill="none"`），与官方那几个 outline 图标同族 |
| 虚线 | `stroke-dasharray: 1.6 1.1`，两个图标共用同一个值，断口密度与相位一致 |

**`IconVirtualWorkspace16`：虚线文件夹 + 右上角开口里的加号。** 文件夹表达「把若干
东西收在一起」，加号表达「新建」，合起来读作「新建一个分组」。**构图与官方的
`IconProjectAddOutline16` 同源**：官方那个也是一个右上角开口的框，加号坐在开口里
并探出右缘；本包沿用同一套「开口方位 + 加号位置」，只把框换成虚线文件夹。文件夹
部分走虚线是它与相邻实线文件夹（代表真实工作区）一眼可分的依据。

加号与文件夹壁同粗（都是 `1.3`），线端**平头**：官方那份加号就是平头、且与容器壁
同粗，改成圆头会让四臂长出半格并粘到缺口边上。

**官方文件夹是填充字形，不能照抄它的 `d`。** `IconFolderClose16` 的 `d` 描述的是
外/内边界（壁半宽 `0.65`），直接拿来描边会画出「内外轮廓」而非一条中线，成品比官方
矮约 `3px`（`14x11` vs 官方 `14x14`）——与旁边的官方文件夹并排就是「小一圈」。正解
是取它的中线：x `1.5~14.5`、y `2.429~13.5863`、圆角 `1.6736`，按 `1.3` 壁厚描出来
与官方填充版落在同一个尺寸域。这条是**枚举像素墨迹范围**量出来的，不是目测。

**小尺寸必须实测，不能靠看矢量放大图。** 字形定稿前筛掉了十余个候选，失败原因分
三类：**加号与轮廓粘连**（开口位置和加号尺寸稍有偏差就糊成一块）、**虚线被加号
吃掉**（断口正好落在加号附近，缺口读不出来）、**开口过窄**（右上角只剩一条缝，
加号像压在线上）。只画文件夹不带加号会把「新建」这件事丢掉——图标本身读不出
动作，只能靠旁边的文字。

做法是渲染出候选、按真实的 16px 栅格化，再按最近邻放大成像素图逐个看——直接看
矢量放大图会掩盖小尺寸的粘连，而不放大又看不清。同一条做法也用来确认它与官方
邻居（文件夹、加号、滑杆、放大镜）并排时不撞形，以及**量墨迹范围**确认尺寸同域。
`test/icons.test.tsx` 固化这两个字形的几何，防止后续被改成「看着差不多」的近似值。

**`IconVirtualFolder16`：虚线文件夹，表示「像一个工作区但并非真实工作区」。**
工作区分组把若干工作区打包在一起，形状上「像一个工作区」，但它没有目录、没有
会话，不是一个真实工作区——虚线正是 DSH 表达「尚未真实存在 / 占位」的既有语言
（待办清单里未开始的圆圈用 `strokeDasharray="2.4 2.4"`，composer 的工作区占位框
用 `stroke-dasharray='4 4'`）。官方文件夹族（`IconFolderClose16` /
`IconFolderOpen16` / `IconFolderOpenOutline16`）**全是实线**，没有可复用的虚线版，
因此照 `IconFolderClose16` 的中线（x `1.5~14.5`、y `2.429~13.5863`，含右上
页签缺口）自绘一份描边版，保留实线那份的圆角与 `1.3` 壁厚，两者并排时同族可辨。

断口取 `1.6 / 1.1`，这是量出来的：再密（`1.2` 级）在 16px 下糊成一条灰毛边，
虚线读不出来、只像画质差；再疏（`2.8` 级）则左下角出现几乎断开的缺口，轮廓像
没画完。它与官方文件夹的差异因此只是「虚线 vs 实线」这一个变量。
