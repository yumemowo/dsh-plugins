# 自绘图标

官方 primitives 的导出表里没有工作区分组所需的字形，也没有图钉。`src/client/icons.tsx` 因此自绘四个图标：`IconVirtualWorkspace16`（新建工作区分组入口与菜单项）、`IconVirtualFolder16`（工作区分组行）、`IconPinOutline16` / `IconPinFill16`（置顶按钮两态）。它们的构图依据、尺寸测量方式与被否掉的造型如下。

自绘不等于另立规范：图形的取值逐条对齐官方 primitives。优先复用官方原语指的是复用接口与控件，不是说字形只能用现成的那几个。

## 共用规范

文件夹族的两个字形共用官方 `IconFolderClose16` 的文件夹轮廓。四项取值逐条对齐官方 primitives 的内联 SVG：

| 项 | 取值 |
| --- | --- |
| `viewBox` / 内联方式 | `0 0 16 16`，与官方一样内联，不带 `xmlns`（官方那几个也没有） |
| 颜色 | 一律 `currentColor`，继承所在行的文字色，不写死主题色 |
| 轮廓 | 官方 `IconFolderClose16` 的中线：x `1.5~14.5`、y `2.429~13.5863`、圆角 `1.6736` |
| 壁厚 | `stroke-width: 1.3`，线端 `round` |
| 绘制方式 | 只用描边（`fill="none"`），与官方那几个 outline 图标同族 |
| 虚线 | `stroke-dasharray: 1.6 1.1`，两个字形共用同一个值，断口密度与相位一致 |

**官方文件夹是填充字形，不能照抄它的 `d`。** `IconFolderClose16` 的 `d` 描述的是外/内边界（壁半宽 `0.65`），直接拿来描边会画出「内外轮廓」而非一条中线，成品比官方矮约 3px（`14x11` vs 官方 `14x14`）——与旁边的官方文件夹并排就是「小一圈」。正解是取它的中线，按 `1.3` 壁厚描出来，与官方填充版落在同一个尺寸域。

虚线断口取 `1.6 / 1.1` 是量出来的：再密（`1.2` 级）在 16px 下糊成一条灰毛边，虚线读不出来、只像画质差；再疏（`2.8` 级）则左下角出现几乎断开的缺口，轮廓像没画完。它与官方文件夹的差异因此只是「虚线 vs 实线」这一个变量。

## 文件夹：实线与虚线

**`IconVirtualFolder16`：虚线文件夹，表示「像一个工作区但并非真实工作区」。** 工作区分组把若干工作区打包在一起，形状上像一个工作区，但它没有目录、没有会话，不是一个真实工作区——虚线正是 DSH 表达「尚未真实存在 / 占位」的既有语言（待办清单里未开始的圆圈用 `strokeDasharray="2.4 2.4"`，composer 的工作区占位框用 `stroke-dasharray='4 4'`）。官方文件夹族（`IconFolderClose16` / `IconFolderOpen16` / `IconFolderOpenOutline16`）全是实线，没有可复用的虚线版，因此按上面的共用规范自绘一份描边版。

**`IconVirtualWorkspace16`：虚线文件夹 + 右上角开口里的加号。** 文件夹表达「把若干东西收在一起」，加号表达「新建」，合起来读作「新建一个分组」。构图与官方的 `IconProjectAddOutline16` 同源：官方那个也是一个右上角开口的框，加号坐在开口里并探出右缘；本包沿用同一套「开口方位 + 加号位置」，只把框换成虚线文件夹。

加号与文件夹壁同粗（都是 `1.3`），线端平头：官方那份加号就是平头、且与容器壁同粗，改成圆头会让四臂长出半格并粘到缺口边上。

文件夹部分走虚线，是它与相邻实线文件夹（代表真实工作区）一眼可分的依据。只画文件夹不带加号会把「新建」这件事丢掉——图标本身读不出动作，只能靠旁边的文字。

## 图钉：置顶按钮的两态

官方 primitives 的导出表里没有任何图钉字形，置顶按钮因此需要自绘。三个部件就是图钉的三段：钉帽、向钉尖收拢的钉身、钉子。

| 项 | 取值 |
| --- | --- |
| 钉帽 | `M6.80 3.12L12.88 9.20`，线端 `round` |
| 钉身（描边） | `M6.80 3.12L7.15 8.85L12.88 9.20`，折角 `round` |
| 钉身（填充） | `M6.80 3.12L7.15 8.85L12.88 9.20Z` |
| 钉子 | `M7.15 8.85L4.18 11.82`，线端 `round` |
| 壁厚 | 与文件夹同族的 `1.3` |

**斜 45°：正交的读成过滤器。** 钉帽水平、钉子竖直时，钉帽那条横线加上向下收拢的钉身正是漏斗的形状，再加一枚钉子更像「筛选」。斜 45° 之后钉帽与钉子错开，图钉的轮廓才立得住。

**坐标按 45° 轴算出来，而不是把正向版本整体 `rotate()`。** 旋转会把每段描边推离像素栅格，拐角处糊成一团：试过绕三个不同的中心各转 45°，钉身与钉子都粘连、钉尖还带上了灰度拖影。改为直接按轴向参数求三个端点，三条线段各自落在格点上。

**墨迹范围量出来是 x `3~13`、y `2~12`**，与官方文件夹（y `2.429~13.5863`）同域，与放大镜等 16px 图标并排时不会一个大一个小。

**两态是同一枚图钉，差别只有「描边 / 填充」这一个变量。** 钉帽与钉子逐点相同，钉身从描边换成填充。置顶态因此不只靠颜色：色阶在浅色主题下对比有限，实心与描边才是一眼可分的差别。

**钉帽与钉子端头必须一起用 `round`。** 只给其中一处，两端在 16px 下会一个圆一个方，同一个字形里出现两种线端。

被否掉的造型与原因：

| 造型 | 否掉的原因 |
| --- | --- |
| 正向（钉帽水平、钉子竖直） | 16px 下读成过滤器 |
| 矩形钉身 + 竖线钉子 | 读成一张小桌子，钉身与钉子之间没有「收拢」这个动作 |
| 钉身占满 `4.4~11.6` | 填充版变成一块实心方块 |
| 尖角折角 | 16px 下尖角被栅格吃掉，钉身读成一个实心三角 |
| 钉子短于 `13.6` | 整体像一个带柄的碗，「钉」读不出来 |
| 整体 `rotate(45deg)` | 描边被推离像素栅格，拐角粘连、钉尖带灰度拖影 |

## 尺寸与形态的实测方式

**小尺寸必须实测，不能靠看矢量放大图。** 做法是渲染出候选、按真实的 16px 栅格化，再按最近邻放大成像素图逐个看——直接看矢量放大图会掩盖小尺寸的粘连，而不放大又看不清。同一条做法也用来确认它与官方邻居（文件夹、加号、滑杆、放大镜）并排时不撞形，以及量墨迹范围确认尺寸同域（`magick ... -depth 8 gray:-` 枚举墨迹的行列范围）。

文件夹字形定稿前筛掉了十余个候选，失败原因分三类：加号与轮廓粘连（开口位置和加号尺寸稍有偏差就糊成一块）、虚线被加号吃掉（断口正好落在加号附近，缺口读不出来）、开口过窄（右上角只剩一条缝，加号像压在线上）。

`test/icons.test.tsx` 固化这些几何，防止后续被改成「看着差不多」的近似值：两个文件夹字形的取值、图钉两态共用同一份钉帽与钉子、45° 轴的对角线位移相等（钉帽两端 `dx ≈ dy`），以及那三个端点的数值与墨迹同域。
