# 自绘图标

官方 primitives 的导出表里没有工作区分组所需的两个字形，`src/client/icons.tsx` 因此自绘 `IconVirtualWorkspace16`（新建工作区分组入口与菜单项）与 `IconVirtualFolder16`（工作区分组行）。它们的构图依据、尺寸测量方式与被否掉的造型如下。

自绘不等于另立规范：图形的取值逐条对齐官方 primitives。优先复用官方原语指的是复用接口与控件，不是说字形只能用现成的那几个。

## 官方图标的取用

dsh 0.1.7-rc.1 把 primitives 的图标导出表改成了「字形名 + 线宽变体」：`IconFolderClose16` 这类带尺寸后缀的老名字全部消失，同一个字形改由 `IconFolderCloseRegular`（1px）与 `IconFolderCloseMedium`（1.3px）两个变体提供。本包一律取 `Regular`，与官方侧边栏行内图标的取值一致。

同一版里新增了图钉（`IconPinOutlineRegular` / `IconPinFillRegular`）、`IconWorkspaceTreeOutlineRegular`、`IconSlidersTwoOutlineRegular` 等字形，语义吻合的几处因此改用官方图标，不再自绘。

| 位置 | 先前 | 现在 |
| --- | --- | --- |
| 置顶按钮两态 | 自绘图钉 | 官方 `IconPinOutlineRegular` / `IconPinFillRegular` |
| 行内「新建会话」按钮 | 官方 `+` | 官方 `IconNewChatOutlineRegular`（官方工作区行在 0.1.7-rc.1 换成了这个字形） |
| header 视图选项入口 | `IconPersonalizationOutline16` | `IconSlidersTwoOutlineRegular`（官方 header 在 0.1.7-rc.1 换成了这个字形） |
| 视图选项面板里的嵌套开关 | 自绘虚线文件夹 | `IconWorkspaceTreeOutlineRegular`（官方「按工作区树分组」那一项用的就是它） |

## 共用规范

文件夹族的两个字形共用官方 `IconFolderCloseRegular` 的文件夹轮廓。四项取值逐条对齐官方 primitives 的内联 SVG：

| 项 | 取值 |
| --- | --- |
| `viewBox` / 内联方式 | `0 0 16 16`，与官方一样内联，不带 `xmlns`（官方那几个也没有） |
| 颜色 | 一律 `currentColor`，继承所在行的文字色，不写死主题色 |
| 轮廓 | 官方 `IconFolderCloseRegular` 的中线：x `1.5~14.5`、y `2.429~13.5863`、圆角 `1.6736` |
| 壁厚 | `stroke-width: 1.3`，线端 `round` |
| 绘制方式 | 只用描边（`fill="none"`），与官方那几个 outline 图标同族 |
| 虚线 | `stroke-dasharray: 1.6 1.1`，两个字形共用同一个值，断口密度与相位一致 |

**官方文件夹的 `d` 描述的是外 / 内边界，不能照抄。** 它的壁半宽是 `0.65`，直接拿来描边会画出「内外轮廓」而非一条中线，成品比官方矮约 3px（`14x11` vs 官方 `14x14`）——与旁边的官方文件夹并排就是「小一圈」。正解是取它的中线，按 `1.3` 壁厚描出来，与官方那份落在同一个尺寸域。

虚线断口取 `1.6 / 1.1` 是量出来的：再密（`1.2` 级）在 16px 下糊成一条灰毛边，虚线读不出来、只像画质差；再疏（`2.8` 级）则左下角出现几乎断开的缺口，轮廓像没画完。它与官方文件夹的差异因此只是「虚线 vs 实线」这一个变量。

## 文件夹：实线与虚线

**`IconVirtualFolder16`：虚线文件夹，表示「像一个工作区但并非真实工作区」。** 工作区分组把若干工作区打包在一起，形状上像一个工作区，但它没有目录、没有会话，不是一个真实工作区——虚线正是 DSH 表达「尚未真实存在 / 占位」的既有语言（待办清单里未开始的圆圈用 `strokeDasharray="2.4 2.4"`，composer 的工作区占位框用 `stroke-dasharray='4 4'`）。官方文件夹族（`IconFolderCloseRegular` / `IconFolderOpenRegular` / `IconFolderOpenOutlineRegular`）全是实线，没有可复用的虚线版，因此按上面的共用规范自绘一份描边版。

**`IconVirtualWorkspace16`：虚线文件夹 + 右上角开口里的加号。** 文件夹表达「把若干东西收在一起」，加号表达「新建」，合起来读作「新建一个分组」。构图与官方的 `IconProjectAddOutlineRegular` 同源：官方那个也是一个右上角开口的框，加号坐在开口里并探出右缘，本包沿用同一套「开口方位 + 加号位置」，只把框换成虚线文件夹。

加号与文件夹壁同粗（都是 `1.3`），线端平头：官方那份加号就是平头、且与容器壁同粗，改成圆头会让四臂长出半格并粘到缺口边上。

文件夹部分走虚线，是它与相邻实线文件夹（代表真实工作区）一眼可分的依据。只画文件夹不带加号会把「新建」这件事丢掉——图标本身读不出动作，只能靠旁边的文字。

## 尺寸与形态的实测方式

**小尺寸必须实测，不能靠看矢量放大图。** 做法是渲染出候选、按真实的 16px 栅格化，再按最近邻放大成像素图逐个看——直接看矢量放大图会掩盖小尺寸的粘连，而不放大又看不清。同一条做法也用来确认它与官方邻居（文件夹、加号、滑杆、放大镜）并排时不撞形，以及量墨迹范围确认尺寸同域（`magick ... -depth 8 gray:-` 枚举墨迹的行列范围）。

文件夹字形定稿前筛掉了十余个候选，失败原因分三类：加号与轮廓粘连（开口位置和加号尺寸稍有偏差就糊成一块）、虚线被加号吃掉（断口正好落在加号附近，缺口读不出来）、开口过窄（右上角只剩一条缝，加号像压在线上）。

`test/icons.test.tsx` 固化这些几何，防止后续被改成「看着差不多」的近似值：两个文件夹字形的取值，以及两个字形共用同一份虚线断口。

`test/bundle.test.ts` 另外守住另一侧：产物里不得再出现 0.1.7-rc.1 已经不导出的那一批老图标名。运行期解析到 `undefined` 会让整棵挂载失败，而单测直接 import 源码看不见这一层。
