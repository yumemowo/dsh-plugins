# 会话行指示器的备选方案

会话行的状态指示器占着树形结构的第一格图标列，本包把它与「会话」小标题绑在一起：指示器在空闲态留空，
于是「这几行是会话」只能靠一段小标题讲。嵌套变深后，每个体内都可能冒出一条小标题，浅灰、无图标、无折叠，
读起来与容器行混作一团。这里记录这个问题的几种解法各自的实际后果。

`indicator-mockups.html` 是可直接打开的对照稿，六个方案并排成一行、**横向滚动**（卡片本身不换行）。

**功能基线一致靠结构相同拿到，不靠共享状态，也不靠留白**：六张卡片的头部行数、控件种类与文案行数全部相同，
因此六棵树天然从同一条线开始（实测 `treeTop` 极差为 `0`，头部没有任何 `min-height` 补白）。
卡片里的按钮只作用于本卡片；要横向比对同一档收起态时用顶部那排按钮一次推平六张。
唯一做成全局的是「平铺」——它换的是整个列表的形态。
另有文字左缘参考线、小标题对齐修正、后代数量等开关。

**指示器内缩滑块只在 ⑤⑥ 两张卡片里**——①–④ 的指示器占的是行内那一列，根本不读这个量，
给它们放滑块就是个没有作用的控件。⑤ 与 ⑥ 也各只管自己那一个值（⑤ 读 `--ind-inset`、⑥ 读 `--ind-inset-icon`），
因此滑块显示的是单个数值，而不是 `4 / 6` 那种「到底哪个生效」的写法。
下面这些数字都是从那张页面量出来的。

## 现状的几何

以 `packages/dsh-workspace-plus` 自身那一层（`--wg-depth=1`）为例：

| 行 | 图标列 | 标题左缘 |
| --- | --- | --- |
| 未归组的会话 | `40–56` | `60` |
| 会话分组内的会话 | `56–72` | `76` |
| 同层的工作区名 / 分组名 | `40–56` / `56–72` | `46` / `78` |
| 「会话」小标题 | — | `72` |

**会话行内先占掉一格图标列，标题因此比同层容器名多缩一格**：未归组会话 `60` 对工作区名 `46`（差 `14px`，
其中 `16px` 是那一格，标题 4px 外边距与容器行 6px `gap` 又各自抵掉一点）；组内会话 `76` 对分组名 `78`。
身份全靠图标列里的字形承担：文件夹、分组箭头、状态点。**空闲会话那一格是空的**，所以「这行是会话」读不出来。

顺带量到一处现状就有的偏差：**小标题的文字 x=72，而它标注的会话标题 x=60（未归组）**，反而偏右 12px。
小标题的 `padding-left` 与会话行同值，但会话行内先占了一格 16px 图标列、再加 4px 标题外边距，
于是小标题落点与会话标题并不对齐——它是按「行左缘」而非「文字左缘」对齐的。
对照稿里的「会话小标题对齐会话标题」开关就是修这一处。

## 六种解法

| # | 做法 | 一句话后果 |
| --- | --- | --- |
| ① | 现状：常驻占位、闲置留空 | 小标题必需 |
| ② | 闲置时整格移出文档流，只在真的有指示器时右推标题 | 闲置落在容器图标列，活跃落在容器名列 |
| ③ | 占位不变，闲置也画中性点 | 几何零改动，列不再可空 |
| ④ | 占位不变，字形换成状态色条 | 文本左缘不动，状态改用形状与颜色 |
| ⑤ | 去掉整列，状态落在行底色与左侧 3px 色条上 | 文本永久左移一格，不随状态变化 |
| ⑥ | ⑤ 的底色 + 官方状态图标，绝对定位在行最左侧 | 文字位置同⑤；图标与文字间距随深度线性拉开 |

### ② 的问题：位移量等于一个缩进步长

| 行 | ② 闲置（无状态） | ② 活跃（有状态） | 差值 |
| --- | --- | --- | --- |
| 未归组会话 | `44` | `60` | `16` |
| 分组内会话 | `60` | `76` | `16` |

闲置落在**容器图标列**里（`44` 在 `40–56` 内），活跃落在**容器名列**上（`60` 对工作区名 `46`），
两者相差正好 `16px`——树的缩进步长。
于是这不是轻微错位，而是一整层的层级跳变：活跃行读起来像一个容器而不是叶子，
未归组会话段的第一行尤其糟（它上方紧邻的就是分组头，同列后读成"分组头的同级"，下面那些闲置行反倒像它的内容）。

位移由状态迁移驱动，所以每个回合发消息时标题右跳一次、跑完打开它时再跳回来；标题的省略号位置也跟着变。

### ⑥ 的取舍：图标与文字的距离随深度拉开

⑥ 把图标钉在**行左缘（容器栏最左侧，`6px`；色条 `4px`）**，绝对定位因此不占布局宽度，文字位置与 ⑤ 完全一致。
代价是图标与文字的间距随深度线性拉开：

| 行 | 图标 x | 文字 x | 间距 |
| --- | --- | --- | --- |
| `--wg-depth=1` 的未归组会话 | 6 | 44 | 38px |
| `--wg-depth=2` 的未归组会话 | 6 | 60 | 54px |
| `--wg-depth=2` 的分组内会话 | 6 | 76 | 70px |
| `--wg-depth=4` 的组内会话 | 6 | 92 | 86px |

深层级时图标与它修饰的那一行相隔 86px、中间横穿数条引导线。

**落地时接受了这个代价**，理由是指示器的职责是「标出这一行在容器栏的位置」，而不是「紧贴标题」：
钉在行左缘之后，指示器与容器行的图标列、折叠箭头落在同一条竖线上，竖着扫一列就能看出哪些会话在跑；
若改成跟着标题缩进走，深层级下这一列会呈锯齿状，反而更难扫。而且状态本身还有底色可以看，
图标不是唯一的信息通道。⑤ 没有这处张力，是因为色条本身没有指向语义（它是一条边缘装饰），
但两种样式共用同一落点，因此「图标 / 色条」切换时几何零变化。

### 图标本身的语义

官方 `StateDot` 只有 `ongoing` / `done` / `warning` 三个状态，空闲不画点。本包 `rowStatusDot` 的判据是
「主状态是 `done` 且 `completed` 为假时返回 `undefined`」，与官方 `SessionNodeItem` 的 `showStatus` 相同。
官方 `StateDot.module.css` 里确实有 `.dot[data-state='idle']` 这条规则（`--dsw-alias-state-idle-primary`），
但那是官方给别处用的，本包从不给它传 `idle`。因此：

- **③ 是唯一有意画灰点的方案**（那一格的语义就是"这行是会话，当前空闲"）。
- **⑤ 与 ⑥ 的闲置行左缘应当是空的**，与 ② 同一取舍。
- ⑥ 的底色只挂在活跃 / 待交互行上，闲置行保持透明。

## 收起态：指示器帮不上忙

把页面全部收起后，六个方案剩下的可见行**完全相同**：

```
虚拟分组 dsh plugins@31
工作区   dsh_plugins@47
```

指示器只存在于会话行，收起时会话行全都不在，因此六个方案的差别归零。收起态的可读性是**另一个问题**，
决策点在撑开体设计而不在指示器：

1. **收起的工作区行没有任何计数。** 分组头有会话数（沿用官方 `section.sessions` 的做法），
   工作区行没有——收起一个工作区后，界面上没有任何东西说明它里面有多少内容。对照稿的
   「收起时显示后代数量」开关就是补这一格，取"会话 + 子工作区"的总数。
2. **文件夹图标是现有唯一的容器信号**，但它只说"我是容器"，不说"我里面有东西 / 有多少"，
   开合两态只表达自己的展开状态。
3. **深度信息随子树一起消失。** `data/nest.ts` 的 `levelOf` 算的是渲染让位格数，只在展开态经 `--wg-depth`
   变成缩进；收起后整棵子树不渲染，没有任何持久化的层级提示。

## 采用的是 ⑤⑥ 的合体

最终落地的是**两种样式做成一对可切换的偏好**（视图选项面板里的「指示器」一组，取值存浏览器本地）：

| 选项 | 落地形态 |
| --- | --- |
| 图标（默认） | ⑥ 的底色 + 官方 `StateDot`，绝对定位在行最左缘、内缩 `6px` |
| 色条 | ⑤ 的底色 + 一根 `3px × 20px` 圆角竖条，内缩 `4px`（靠左对齐，不在那 16px 的盒里居中） |

两者共用同一套底色与选中态，因此「图标 / 色条」只换字形。落点**不跟缩进走**：绝对定位在行的最左缘（容器栏左缘），与层级深度无关，因此同一段里所有会话行的标题落在同一条竖线上。图标是 16px 方块，比 3px 宽的色条多缩 2px——完全贴行左缘会读成行的边界，内缩之后才像浮在行里。
那 16px 宽的盒是给官方图标用的，**色条不在里面居中**：居中会让它左缘落到 `内缩 + 6.5px` 上，比设计稿右移 6.5px。

**「会话」小标题随之去掉**：会话行比同级容器多让出一格（未归组 `24 + 16d`、组内 `40 + 16d`），指示器又不占行内流，三段靠缩进就分得开。落地时同步改了 `WorkspaceSection.tsx` / `GroupSection.tsx` 两处渲染条件、`test/nestingDom.test.tsx` 与 `test/styles.test.ts` 里钉住小标题的用例，以及 `docs/sub-workspace-nesting.md` 那节论证。

## 选中态：把底色加深一档

底色被状态占用之后，「当前会话被选中」失去了表达位置。落地采用**把底色加深一档**。

先把官方那条摆出来，它是**一条声明、一个值**：

```css
.YDXeBa_projectRow:hover,.YDXeBa_sessionRow:hover,.YDXeBa_sessionRow.YDXeBa_selected{
  background:var(--dsw-alias-interactive-bg-hover)
}
```

也就是 **hover、active(selected)、hover+active 三者同色**——官方没有「叠一层」这回事，也没有任何边框。
（早先把这一档写成「叠层浅灰」是错的。）

- **无强调色的行（空闲、完成）与官方完全一致**：悬停与选中同为 `--dsw-alias-interactive-bg-hover`，
  用的也是 `background-color` 同一个属性同一个值，不叠第二层——叠两次会造出官方没有的颜色；
- **只有带强调色的行才加深**：同色相从 `10%` 提到悬停 `18%`、选中 `26%`，色相仍说明是哪种状态，深浅说明「指针在上面」还是「这是当前会话」；
- 强调色行**不叠灰**：`--dsw-alias-interactive-bg-hover` 是中性灰，压在饱和蓝上会把色相稀释成糊色；
- **完成态不参与状态底色**，它的选中与空闲同档——完成那次提醒已经由指示器的绿色表达，给底色会让整段长期泛色。

**落地版本一条描边都不加**：官方的 active / selected 只有底色（`sessionRow.selected` 与 `:hover` 是同一条声明），
本包早先给「色条」样式额外加过一条 `inset box-shadow` 内侧描边，那与设计和官方都不一致，已移除。
对照稿里另外三种通道（叠层 + 内描边 / 只内描边 / 淡叠层 + 加字重）以及「还原现状」那一档仍然保留，可以现场对比；
`indicator-mockups.html` **每张卡片**上的「选中态」下拉就是切换这几档的。**默认值随样式而定**：
①–④ 默认「官方（同色）」（那边底色透明，选中本来就没问题），⑤⑥ 默认「加深一档」；
两边的**控件与可调档位完全一致**，差的只是默认取哪一档——这才叫功能基线一致。

## 尚未决定

- **收起态那三格**（工作区计数、文件夹语义、折叠延续标记）要不要做，以及做成什么形状。
- **平铺列表**：官方平铺行与树形行**共用同一个 `sessionRow`**，缩进都从 `8px` 起（平铺不设 `--dsh-workspace-indent`）。
  本包只有 ⑤⑥ 两种样式，指示器都出了行内流、占掉行左缘 `4~20px`，因此平铺行取 `24px` 让标题避开它——
  这样标题落在官方同一条线（`28px`）上。①–④ 那种「指示器留在行内」的写法若将来落地，平铺就该回到 `8px`。
