# 会话折叠

一个展示范围内的会话默认只露出最近的几条，其余由一条「展开其余 N 个会话」按钮收起来。官方的 `sidebar.workspaces` 也有这条按钮，本包沿用它的控件与文案，只把「露出几条」的判据换成时间的。

## 展示范围

折叠按**展示范围**独立计算，几个范围之间互不影响：

| 范围 | 落在哪 |
| --- | --- |
| 一个工作区的未归组会话 | 该工作区撑开体里、没有分组头的那一段 `.sessions` |
| 工作区内的一个会话分组 | 分组撑开体里的那一段 `.sessions` |
| 末尾「未分组」桶 | 根节点上那个隐式容器，工作区被删除后遗留的会话落在里面 |

因此「工作区 ws 下的直接会话」与「ws 下分组 g 里的会话」是两个独立的额度与两个独立的展开态：展开其中一个，另一个照旧折叠。子工作区各自是一个完整工作区，它的未归组会话与它自己的会话分组同样是独立范围。

平铺（「单列表」展示方式）与搜索结果页不折叠：平铺没有容器这一层，搜索结果按条数上限截断。

## 额度

一段范围内展示几条，按顺序走下面五步，任一步定下成员集合即结束：

1. 整段条数不超过 3：没有可收起的东西，全部展示。
2. 置顶超过 5 条：只留全部置顶，额度不再约束，跳到第 5 步。
3. 否则沿传入顺序补上 3 天内用过的行（含未处于空闲状态的那些），总数到 5 条为止。
4. 补完仍不足 3 条：沿传入顺序继续补 3 天之外的，补到 3 条为止。
5. 不论走到哪一步，未处于空闲状态的行一律补上。

窗口是 **3 天**：超过 3 天没被用过、又没有置顶的会话，下一次点开大概率是归档，默认因此收起来。但一条都不露会让范围看起来是空的，所以下限是 3 条。

第 3 步的 5 条**是总数**，置顶行与未空闲的行都算在里面，不是额外叠加。截图里那个分组（3 条旧置顶 + 当前会话几分钟前更新）走到第 3 步得到 4 条：3 条置顶都在窗口之外，5 条的上限还剩 2 个名额，窗口内那 1 条补上。若按「置顶不吃名额」或「额度由窗口内的条数单独推出」来算，这里只会露出 3 条。

窗口以内的未空闲行由第 3 步按自己的更新时间一起计数，落选的才由第 5 步补——两类行可能让总数超过 5：

- 新建中的空白会话
- 会话自己正在运行的行
- 名下有运行中子代理的行

一个跑了 4 天的会话被折起来是这套额度最不该发生的事，因此它即使落在窗口之外也由第 5 步补上。

三个数字都在 `src/client/data/collapse.ts`（`COLLAPSED_SESSION_LIMIT_MAX` / `COLLAPSED_SESSION_LIMIT_MIN` / `RECENT_WINDOW_MS`），改数字要改代码、重新构建客户端产物。

## 与置顶的配合

置顶会话在「置顶区 + 分组内」显示方式下（视图选项里的 `置顶区 + 分组内`）**始终全部展示并占额度**：

- 置顶条数超过 5 时整段置顶照常全部露出，额度上限被越过，普通行一条也不顺补；
- 置顶不足 5 条时，普通行按额度顺补剩下的名额。

例如 2 条置顶加窗口内用过的 5 条会话露 5 条（2 条置顶 + 3 条顺补），6 条置顶则露 6 条。这是五步判定中第 2 步与第 3 步的直接结果：第 3 步的上限数的是总数，置顶已经在里面占掉名额。

「仅置顶区」显示方式下置顶行不享受这条豁免，按普通行一起折叠。这不丢信息：被折掉的置顶会话仍在上方那块常驻的置顶区里。

折叠收到的输入是「本范围内哪些行始终展示」这份已经定好的名单，不是置顶名次表。名次表是排序那侧的形状：它的空同时意味「没有置顶行」与「不在就地置顶档」，消费方拿到它先得分辨是哪一种。档位判断因此留在区域容器一处，比较器拿名次表（排序用得到次序），折叠拿从它收成的集合 `alwaysVisibleIds`。

## 按钮与展开态

- 文案取官方 `workspace` 语言包的 `sessions.expand`（`展开其余 {n} 个会话`）与 `sessions.collapse`（`收起`），`n` 是这一档算出的被收起条数。
- 一条也不多时整条按钮不渲染，与官方一致。
- 点按钮在「全部行」与「额度内的行」之间切换。
- 展开态是浏览器内的临时界面状态，不落盘。所在容器（工作区或会话分组）收起时它一并收回，与官方收起工作区时重置额度同一取舍。
- 展开态按范围各存一份，因此两个范围的开合不会互相影响。
- 从搜索结果打开一条会话时，若那条行正被折起来，本范围整体撑开（与官方把该范围的额度置成无限同一取舍）。结果行的意图是「去看这条会话」，行不在文档里就无从滚进可视区；展开按钮随后照常可以把它收回去。

## DOM 与样式

按钮是所在 `.sessions` 段的最后一个直接子项，与同段会话行共用一条缩进线：`rows.module.css` 里那两条按容器写的规则把 `.row` 与 `.sessionOverflow` 写在同一组选择器里，缩进表达式因此只有一处。按钮文字再补上 `.rowTitle` 的左外边距，左缘于是压在会话标题那条线上（官方那条按钮同样如此）；间距走既有的 `.sessions > * + *`，按钮不必自己写 `margin`。

几何与配色照官方 `.sessionOverflowButton`：`28px` 高、`12px` 字、`label-tertiary` 转 `label-secondary`。按钮与行一起参与所在撑开体的逐个淡入。

少了那个补偿量时六个落点会一起偏 4px，DOM 结构与选择器断言都看不出来，因此由 `scripts/probes/session-collapse-indent.mjs` 在真实浏览器里逐个落点量：

```sh
pnpm run build
node scripts/probes/session-collapse-indent.mjs
```

它按编译后的类名拼出「两种容器 × 三个缩进层级」六个范围，逐条比对按钮文字左缘与会话标题左缘，退出码非零即有不符。

行元素由调用方渲染（工作区内的行与「未分组」桶里的行菜单不同），`SessionList` 只按 id 排布它们，因此不复制那一部分取舍。

## 判定与顺序

**传入的 `rows` 就是展示顺序，折叠不重排**：步骤 3、4 沿传入顺序取，`updatedAt` 只用来判「窗口内还是窗口外」，不参与排序。

当前展示顺序恰好由 `updatedAt` 决定（三种段落都按本包既有的比较器排：置顶名次、空白最前、其余按最近更新倒序），两条因此一致。但两者是**分开的**，等展示顺序能自定义，窗口判据就要重定，见下一节。

这也是「未分组」桶需要的行为：那一段保持会话列表原序，折叠跟着它走才不会把用户看到的排在前面的行折掉。

## 将来接自定义顺序时要改哪里

本包不提供会话拖拽（README 的「已知限制」列着），因此下面这份是给后续实现做参考的，不是现有行为的描述。依据是官方 `dsh-client-ui-workspace` 0.2.0-rc.2 的 `reconcileManualOrder`、`sessionDragOrder` 与 `commitSessionDrag`。

### 顺序是投影，不是存储

官方把展示顺序拆成四段拼起来，`ordered` 只收还没被前面认领的 id，四段因此互不重叠：

| 分区 | 内容 |
| --- | --- |
| `pins` | 置顶集合自己的顺序，即注册表 `pinnedSessionIds` 的次序，不按时间重排 |
| `ordered` | 用户拖出来的相对位置 |
| `ordinary` | 剩下的按最近更新倒序，同值用 id 兜底 |
| `archives` | 归档的排最后 |

因此「展示顺序」没有对应的存储，每次都由「全量成员 + 置顶集 + 用户拖出的序 + 时间」重建。落盘的只有 `sessionOrderByAccount`，按容器分键：工作区用 `workspaceId`，平铺列表用 `__flat_session_order__`，未分组桶用空串。

切到手动序时把当前算出的顺序整份存下来当起点，切回「最近更新」就清空（官方 `setOrderBy`）。

### 拖拽在折叠后的视图里算落点

官方的 `commitSessionDrag` 把两个入参分得很清：

- 全量成员 id：该容器真正的成员表，被改动的是这一份；
- 折叠后实际渲染的行：`collapsedSessionRows(...).rows`，只用来判「拖到谁的上方 / 下方」。

`sessionDragOrder` 在动手前有一组否决条件，任一命中就返回 `undefined`（不写盘）：源或目标不在可见行里、源是空白行、源与目标的置顶态不同、源与目标同一行、或源不在该容器的全量成员表里。**折叠决定可拖拽的范围，顺序决定折叠露出谁**，两者互锁。

### 对本模块的三点要求

1. `collapseSessionRows` 的接口不用改。它已经是「按传入顺序取前缀」的纯投影，输入换成重建出来的展示顺序即可。
2. 要重定的是窗口判据。`now - updatedAt <= RECENT_WINDOW_MS` 的前提是「展示顺序由时间决定」；顺序能拖之后，「最近三天内」不再是「用户还惦记着它」的代理，届时的方向大概率是「显式位置优先，时间只作兜底」——正如官方让 `ordinary` 分区里的成员按时间排。
3. `alwaysVisibleIds` 与官方的 `pins` 分区同义，已经对上，不必动。

另有一处只影响本包：末尾「未分组」桶走会话列表原序、不套 `compareSessionRows`，将来若它也支持拖拽，需要自己的序键（官方用的是空串）。
