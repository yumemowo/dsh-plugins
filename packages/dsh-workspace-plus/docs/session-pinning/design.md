# 置顶会话的最终设计

本包在侧边栏工作区区域的顶部增加一块**置顶区**，列出全部已置顶的会话。

这份文档只讲最终设计有哪些元素、各自做什么。取舍过程与被否方案见[设计过程](design-options.md)，落地步骤见[实现计划](implementation-plan.md)，逐项实测见[对照稿](pinning-mockups.html)。

## 位置与层级

区域顶部自上而下是三块：**header**（两行标题 + 搜索槽 + 三个 28px 入口）→ **置顶区** → **工作区列表**。

置顶区与 header 平级，两者都在列表的滚动区**之外**。列表怎么滚，置顶区都留在原位——这与方案 ④ 不同，④ 的置顶段在列表里，往下滚一点就滑走了。

**没有置顶会话时整块不渲染**，不是渲染成空块：段头消失、分隔线消失，那一段空间完整交还给列表。

## 元素

| 元素 | 内容 | 行为 |
| --- | --- | --- |
| 段头 | 箭头 + 「置顶」 + 行尾计数 | 点它收起 / 展开整块；段头**不带图钉图标** |
| 预览行 | 最多 N 条置顶会话（默认 5，可调） | 点行即打开该会话 |
| 行尾提示 | `7 条 · 还有 2 条` | 只在溢出时出现 |
| 分隔 | 一段空白（高度与一条 `1px` 细线加同样的 margin 相同） | 把置顶区与工作区切开 |

段头复用容器行的词汇（16px 图标列里的箭头 + 名字 + 行尾计数），因此「点它收起」不需要额外教。
它**不画图钉**：那枚图标在这一行不承担任何指向，只是装饰。

## 溢出与展开

置顶条数超过可见上限时有两种给法，由一个浏览器本地偏好切换（默认第一种）：

| 模式 | 静止 | 指针移到预览行上 |
| --- | --- | --- |
| `expand`（默认） | 占 5 条高度（超出的行留在文档里、不可见且不可聚焦） | 整块向下浮出，一次列出全部 |
| `scroll` | 占 5 条高度 | 在预览区内滚动 |

两种模式占据的高度**完全相同**（段头 `30px` + 5 条 `168px` = `198px`），因此切换它们不改变布局。
连分隔一起算，置顶区整块常驻 `211px`——那正是它从列表可视高度里扣掉的量。

三处交互决定，都是「别打断手感」：

- **触发区是预览行本身，不含段头。** 段头是一块独立的交互区（管收起 / 展开），把浮出也挂在它上面会让两个意图互相干扰。
- **没有行被裁掉时不接悬停。** 全部置顶会话都已在静止高度里显示时，浮出只是把一个等高的盒子重新定位一遍：指针进入的瞬间换掉定位与底色，读起来是一次没有反馈的闪动。只有溢出时悬停才有意义。
- **静止态不可滚。** 指针一放上去就浮出，滚动在这里没有承载对象；滚动只属于 `scroll` 模式。
- **浮出用绝对定位，不推挤下方内容。** 若把下面的列表推开，指针下的行会自己在动，指针一离开就收起、又推回来，形成抖动。浮出态因此**不占额外内边距、不加描边环**，前 5 行的纵向、横向与标题位置逐格不变。
- **浮出时那一段常驻高度不塌。** 预览区脱离流之后，段本身必须自己占住「段头 + 预览区 + 分隔」那一份高度，否则指针一进入整段就塌成段头一行，下方的工作区列表整体上移。实测修复前下方内容 `top` 由 `211` 跳到 `43`（`168px` 的上移），修复后静止与浮出两态都停在 `211`。
- **展开与收回都有过渡，且过渡的是高度本身。** 预览区**两态都绝对定位**，只让 `max-height` 从「静止高度」过渡到「全部行叠起来的实高」。定位若只在浮出态给，收回时那条规则被摘掉、面板回到流里，段当场从 `211px` 涨到 `279px`——展开方向修好了，收回方向又坏掉。

  过渡目标必须是内容实高。取视口上限（`min(60vh, 640px)`）时，内容远矮于上限，可见高度在过渡前段就走完、剩下的时长只是看不见的 `max-height` 在涨——实测 `180ms` 的过渡里前 `60ms` 就长到了最终高度，读起来就是「没有动画」。

  为此全部置顶行都留在文档里（收回方向要有东西可收），静止时超出可见条数的那些由样式表用 `visibility` 收起，并延后到收回结束才生效——否则收回途中就已经 Tab 不到。可见性是自然状态，过渡没跑或被降频时行只是「没淡入」，不会永远不可见。

**触屏回退**：`(hover: none)` 的设备没有悬停，`expand` 模式在那里不可用，实现按 `scroll` 渲染。

## 行尾的图钉

会话行的行尾是「时间 → 操作位 → 图钉」，两态位置相同：

| 状态 | 排布 | 效果 |
| --- | --- | --- |
| 已置顶 | 时间（悬停隐去）→ 操作位 → **图钉** | 图钉常驻可见并占着 16px，除非时间/操作位显隐，它的位置不变 |
| 未置顶 | 时间（悬停隐去）→ 操作位 → 图钉 | 图钉与操作位同时出现，静止时连宽度一起收掉 |

两种状态的**先后顺序一致**，差别只在图钉是否常驻。未置顶时图钉不占宽——不为一个看不见的状态图标留空位，行尾因此不会凭空多出一格。

## 菜单里的置顶

会话行菜单里也有置顶项，排在官方操作块的最前（重命名之前），与官方 `PinSessionMenuItem` 的次序一致。

| 状态 | 文案 | 字形 |
| --- | --- | --- |
| 未置顶 | 置顶会话 | 描边图钉 |
| 已置顶 | 取消置顶 | 实心图钉 |

文案与字形都取官方 `workspace` 语言包的 `menu.pinSession` / `menu.unpinSession`。

达到置顶上限时该项禁用，但**已置顶的行不受影响**——上限只拦新增，取消置顶始终可点。

行尾的图钉按钮与菜单项并存，与官方一样：行尾那枚管高频切换，菜单项给不习惯找图钉的人一条入口。

## 打开的图钉与取消置顶

- **从置顶区打开一个会话，不切换当前聚焦的工作区。** 置顶区是跨工作区的入口，替用户改聚焦范围会把他正在看的列表换掉。
- **取消置顶当前打开的那个会话时**：
  1. 还有其它置顶会话 → 打开下一条；
  2. 一条不剩 → 把聚焦工作区切回「全部」，并**保持当前会话的打开状态**（不关闭、不导航）。

## 可调项

### 宿主侧（插件的 Config 字段）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 置顶区显示条数 | `5` | 超出部分按上面的模式给 |
| 置顶数量上限 | `20` | 达到上限后置顶按钮转为禁用态 |

这两项声明成插件的 Config 字段，取值经本包既有的 remote 快照下发到浏览器半边。

改法是编辑 profile 的 `cordis.patch.yml`（不是设置页——dsh 不给插件自动生成配置表单，本包也没有注册渲染页，原因见[实现计划](implementation-plan.md)）：

```yaml
- id: workspace-plus
  config:
    pinnedVisibleCount: 3
    pinnedLimit: 8
```

两个字段都标 `.volatile()`，改完不需要重启 `dsh`：新值直接写进插件已持有的引用，下一次快照就带上。

**上限是本包自己实施的，不是宿主的。** 置顶集合归官方的 `ctx.workspaceRegistry`，官方的 `pinSession` 没有上限参数，本包无法让宿主拒绝写入。因此「上限」表现为：达到上限时本包把置顶按钮置为禁用态并给出提示。这与「官方也可能在别处写入置顶」不冲突——官方 `ui-workspace` 的置顶入口只渲染在 `sidebar.workspaces` 里，而那个区域由本包接替，因此本包是当前唯一的置顶入口。

**调低上限不会取消已有的置顶**：上限只拦新增，已置顶的照常显示。

### 浏览器本地（写入 client store）

| 项 | 取值 | 默认 |
| --- | --- | --- |
| 溢出给法 | 浮出 / 区内滚动 | 浮出 |
| 置顶会话显示方式 | 仅置顶区域 / 置顶区域 + 分组内置顶 | 仅置顶区域 |

「置顶区域 + 分组内置顶」在置顶区之外，**同时**让置顶会话在它自己所在的那一段里也排到最前（即方案 ② 的就地置顶）。两种显示方式下置顶区的行为完全一致。

这两项是浏览器本地偏好，与展示方式、指示器样式、折叠态同一套存储，键沿用 `dsh.workspace-plus.view.v1`。

### 折叠态

置顶区可以收起，收起态是**全局**的（各窗口一致），与上面两项同处浏览器本地存储。收起后只剩段头一行，行尾提示改为只报总数（`7 条`）。

## 未决

**置顶区显示的内容是否跟随当前聚焦的工作区？** 这是一条没有讨论过的设计，因此当前默认**显示全部置顶项**，不随聚焦变化。理由有三条：

- 置顶的用途是「跨范围地找到那几条」，跟着聚焦走会让它在最需要跨范围时反而被裁掉；
- 聚焦是「看哪一片」的过滤器，置顶是「我收藏了什么」的清单，两者语义不同层；
- 先显示全部不会丢信息，反过来则会。

若后续论证出有必要，再提供浏览器侧的切换开关。**在此之前不实现。**
