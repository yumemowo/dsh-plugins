# 置顶会话的最终设计

本包在侧边栏工作区区域的顶部增加一块**置顶区**，列出全部已置顶的会话。

这份文档只讲最终设计有哪些元素、各自做什么。取舍过程与被否方案见[设计过程](design-options.md)，落地时改了哪些做法见[实现记录](implementation-notes.md)，逐项实测见[对照稿](pinning-mockups.html)。

## 位置与层级

区域顶部自上而下是三块：**header**（两行标题 + 搜索槽 + 三个 28px 入口）→ **置顶区** → **工作区列表**。

置顶区与 header 平级，两者都在列表的滚动区**之外**。列表怎么滚，置顶区都留在原位——这与方案 ④ 不同，④ 的置顶段在列表里，往下滚一点就滑走了。

**没有置顶会话时整块不渲染**，不是渲染成空块：段头消失、分隔线消失，那一段空间完整交还给列表。

## 元素

| 元素 | 内容 | 行为 |
| --- | --- | --- |
| 段头 | 箭头 + 「置顶」 + 行尾计数 | 点它收起 / 展开整块；段头**不带图钉图标** |
| 预览行 | 最多 N 条置顶会话（默认 5，可调） | 点行即打开该会话 |
| 行尾提示 | `7 条 · 还有 2 条` | 只在溢出时出现 |
| 分隔 | 一段空白（高度与一条 `1px` 细线加同样的 margin 相同） | 把置顶区与工作区切开 |

段头复用容器行的词汇（16px 图标列里的箭头 + 名字 + 行尾计数），因此「点它收起」不需要额外教。
它**不画图钉**：那枚图标在这一行不承担任何指向，只是装饰。

## 溢出与展开

置顶条数超过可见上限时有两种给法，由一个浏览器本地偏好切换（默认第一种）：

| 模式 | 静止 | 指针移到预览行上 |
| --- | --- | --- |
| `expand`（默认） | 占 5 条高度（超出的行留在文档里、不可见且不可聚焦） | 整块向下浮出，一次列出全部 |
| `scroll` | 占 5 条高度 | 在预览区内滚动 |

两种模式占据的高度**完全相同**（段头 `30px` + 段头空隙 `6px` + 5 条 `168px` = `204px`），因此切换它们不改变布局。
段头空隙是段头与首行之间常驻的一段空白：浮出面板要画成四角完整的圆角矩形，顶部的圆弧落在这里。
连分隔一起算，置顶区整块常驻 `217px`——那正是它从列表可视高度里扣掉的量。

三处交互决定，都是「别打断手感」：

- **触发区是预览行本身，不含段头。** 段头是一块独立的交互区（管收起 / 展开），把浮出也挂在它上面会让两个意图互相干扰。
- **没有行被裁掉时不接悬停。** 全部置顶会话都已在静止高度里显示时，浮出只是把一个等高的盒子重新定位一遍：指针进入的瞬间换掉定位与底色，读起来是一次没有反馈的闪动。只有溢出时悬停才有意义。
- **静止态不可滚。** 指针一放上去就浮出，滚动在这里没有承载对象；滚动只属于 `scroll` 模式。
- **浮出用绝对定位，不推挤下方内容。** 若把下面的列表推开，指针下的行会自己在动，指针一离开就收起、又推回来，形成抖动。浮出面板与段头之间的空隙是常驻的，展开因此不挪动任何一行，前 5 行的纵向、横向与标题位置逐格不变；面板画四角完整的 `10px` 圆角，顶部圆弧落在空隙里，既不压段头也不削首行，不加描边环。
- **浮出时那一段常驻高度不塌。** 预览区脱离流之后，段本身必须自己占住「段头 + 段头空隙 + 预览区 + 分隔」那一份高度（`217px`），否则指针一进入整段就塌成段头一行，下方的工作区列表整体上移。实测记录见[实现记录](implementation-notes.md)。
- **展开与收回都有过渡，且过渡的是高度本身。** 预览区**两态都绝对定位**，只让 `max-height` 从「静止高度 + 空隙」过渡到「全部行叠起来的实高 + 空隙」。定位若只在浮出态给，收回时那条规则被摘掉、面板回到流里，整段高度跟着涨到全部行的实高——展开方向修好了，收回方向又坏掉。

  过渡目标必须是内容实高。取视口上限（`min(60vh, 640px)`）时，内容远矮于上限，可见高度在过渡前段就走完、剩下的时长只是看不见的 `max-height` 在涨——实测 `180ms` 的过渡里前 `60ms` 就长到了最终高度，读起来就是「没有动画」。

  为此全部置顶行都留在文档里（收回方向要有东西可收），静止时超出可见条数的那些由样式表用 `visibility` 收起，并延后到收回结束才生效——否则收回途中就已经 Tab 不到。可见性是自然状态，过渡没跑或被降频时行只是「没淡入」，不会永远不可见。

**触屏回退**：没有悬停能力的设备上 `expand` 不可用，按 `scroll` 渲染。这一档由组件派生（`effectiveOverflow`）：无悬停时下发的就是 `scroll` 那一套 DOM，样式表里没有第二份声明。用户偏好本身不被改写，因此插上鼠标后仍回到 `expand`。

## 行尾的图钉

行尾跟官方一样是**两套内容互换**，而不是在一格里加一枚按钮：

| 状态 | 行尾 |
| --- | --- |
| 静止 | 一格静止区：相对时间 · 行尾图标位 ·（已置顶时）**只读图钉标记**，三者按 `gap: 6px` 排开 |
| 悬停 / 菜单展开 / 键盘聚焦 | 整格让位，操作位展开：省略号 · 占用者按钮 · **图钉按钮** |

静止那枚标记不可点，它只说明状态；切换入口是操作位里那枚按钮。两者因此永不同时可见，行尾在任一时刻只有一套内容。

**几何全部照官方 `ui-workspace` 那一套**（静止区 `.rowResting` 的 `gap:6px` 与 `.pinIndicator` 的 16×20、`label-caption`；操作位按钮的 `.iconButton` 盒模型 24×24 配 `-4px` 外边距，槽 `gap:13px`），因此视觉间距在静止态与悬停态都是 `5px`——`6 - 1` 与 `13 - 4 - 4`。静止格与时间之间那 1px 来自官方 `.time` 自带的 `margin-inline-end:-1px`。

三处细节与官方一致，漏一个都会被看成「间距不对劲」：

- 槽的高度交给内容。官方只给工作区行写死 20px，会话行不给；照抄 20px 会把 24px 的按钮上下各裁掉 2px（`overflow: hidden`）。
- 会话行槽里的按钮统一成 24×24 + `-4px`，包括本包的省略号。省略号若留在 16px，它与图钉之间的间距会多出 8px。
- 键盘焦点也是让位条件：焦点落到图钉按钮上时，静止格必须隐去，否则标记与按钮同时可见。

**这一枚必须由本包画。** 官方也往行尾按钮位注册了一枚同形同义的图钉，但它只看官方自己的置顶集合，不认 `pinnedLimit`；两枚并存时上限只在其中一枚上生效。因此本包按 id 把官方那条注册排掉（见 `official-reuse.md` 的「行尾按钮位上本包要排掉的那一枚」），行尾这一枚是唯一的切换入口。

置顶区里的行复用同一套行尾，因此右键与 `...` 都能唤出同一份会话操作菜单。菜单里没有归组项——置顶区是跨工作区的入口，这些会话可能不属于任何工作区。这些行也不挂悬停卡片：已经钉在一段固定的区里，卡片在这里只多一层浮层。

## 菜单里的置顶

会话行菜单里也有置顶项，排在注册表那段之前、全菜单第一个，与官方 `PinSessionMenuItem` 的位置一致。

| 状态 | 文案 | 字形 |
| --- | --- | --- |
| 未置顶 | 置顶会话 | 描边图钉 |
| 已置顶 | 取消置顶 | 实心图钉 |

文案与字形都取官方 `workspace` 语言包的 `menu.pinSession` / `menu.unpinSession`。

达到置顶上限时该项禁用，但**已置顶的行不受影响**——上限只拦新增，取消置顶始终可点。

**这一项由本包自己实现，官方注册进 `session` 的同名项被排掉。** 官方那份只按官方自己的置顶集合与对端权限判断，不知道 `pinnedLimit`；两处入口并存时会出现「菜单里置顶已禁用、行尾按钮却照常可点」或反过来，上限在一处生效、在另一处被绕过。行尾按钮位上的官方图钉同理（见 `official-reuse.md`）。

行尾的图钉按钮与菜单项并存，与官方一样：行尾那枚管高频切换，菜单项给不习惯找图钉的人一条入口。两处落到同一个 `toggleSessionPin`，上限判据因此只有一处。

## 打开的图钉与取消置顶

- **从置顶区打开一个会话，不切换当前聚焦的工作区。** 置顶区是跨工作区的入口，替用户改聚焦范围会把他正在看的列表换掉。
- **取消置顶当前打开的那个会话时**：
  1. 还有其它置顶会话 → 打开下一条；
  2. 一条不剩 → 把聚焦工作区切回「全部」，并**保持当前会话的打开状态**（不关闭、不导航）。

## 可调项

### 宿主侧（插件的 Config 字段）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 置顶区显示条数 | `5` | 超出部分按上面的模式给 |
| 置顶数量上限 | `20` | 达到上限后置顶按钮转为禁用态 |

这两项声明成插件的 Config 字段，取值经本包既有的 remote 快照下发到浏览器半边。同一份配置里还有 `forkFollowsSourceGroup`（默认 `false`），它不属于置顶这件事，说明见 [README](../README.md#分叉出的会话跟随源会话的分组)。

改法是编辑 profile 的 `cordis.patch.yml`（不是设置页——dsh 不给插件自动生成配置表单，本包也没有注册渲染页，原因见[实现记录](implementation-notes.md)）：

```yaml
- id: workspace-plus
  config:
    pinnedVisibleCount: 3
    pinnedLimit: 8
```

两个字段都标 `.volatile()`，改完不需要重启 `dsh`：新值直接写进插件已持有的引用，下一次快照就带上。

**上限是本包自己实施的，不是宿主的。** 置顶集合归官方的 `ctx.workspaceRegistry`，官方的 `pinSession` 没有上限参数，本包无法让宿主拒绝写入。因此「上限」表现为：达到上限时本包把置顶入口（行尾那枚图钉、菜单里那一项）置为禁用态。

这要求**所有置顶入口都由本包提供**。官方原本有两处：`ui-workspace` 的行内图钉与它注册进 `session` 菜单的那一项，两处都只看官方自己的集合。它们都按 id 排掉、换成本包的实现（见 `official-reuse.md`），上限因此没有旁路。

**调低上限不会取消已有的置顶**：上限只拦新增，已置顶的照常显示。

### 浏览器本地（写入 client store）

| 项 | 取值 | 默认 |
| --- | --- | --- |
| 溢出给法 | 浮出 / 区内滚动 | 浮出 |
| 置顶会话显示方式 | 仅置顶区域 / 置顶区域 + 分组内置顶 | 仅置顶区域 |

「置顶区域 + 分组内置顶」在置顶区之外，**同时**让置顶会话在它自己所在的那一段里也排到最前（即方案 ② 的就地置顶）。两种显示方式下置顶区的行为完全一致。

这两项是浏览器本地偏好，与展示方式、指示器样式、折叠态同一套存储，键沿用 `dsh.workspace-plus.view.v1`。

### 折叠态

置顶区可以收起，收起态是**全局**的（各窗口一致），与上面两项同处浏览器本地存储。收起后只剩段头一行，行尾提示改为只报总数（`7 条`）。

## 未决

**置顶区显示的内容是否跟随当前聚焦的工作区？** 这是一条没有讨论过的设计，因此当前默认**显示全部置顶项**，不随聚焦变化。理由有三条：

- 置顶的用途是「跨范围地找到那几条」，跟着聚焦走会让它在最需要跨范围时反而被裁掉；
- 聚焦是「看哪一片」的过滤器，置顶是「我收藏了什么」的清单，两者语义不同层；
- 先显示全部不会丢信息，反过来则会。

若后续论证出有必要，再提供浏览器侧的切换开关。**在此之前不实现。**
